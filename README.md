# ZhixingQuant（知行量化）文档入口

> **本文件是唯一入口。** 无论你是人还是 AI agent，从这里开始。
> 本文件只做两件事：① 告诉你不可协商的约束；② 把你的任务路由到正确的文档。

## 一、三大铁律（不可协商，详述见 [00-项目宪章](docs/00-项目宪章.md)）

1. **文档驱动**：先契约后实现；代码与文档冲突时必须当场裁决，不留"以后再说"。
2. **机器验收**：CI 全绿才算完成，任何人或 AI 口头说"做完了"均不算数。
3. **数据质量门禁一等公民**：策略/回测只读干净区；无门禁的数据源不允许接入。

## 五、给 AI agent 的交接协议

> 仓库根的 `QODER.md` 是本节的自动加载指针（供 agent 工具读取），只路由、不复述规则；本节改了不必同步它，除非起手式步数或入口文件位置变了。

每次新 session 的标准起手式：

1. 读本文件
2. 读 [01-路线图](docs/01-路线图.md)，定位当前 Step：🔵 进行中优先，没有 🔵 就看总览里的 `← 当前位置`
3. 按任务路由表，读该任务涉及的 L2 文档
4. 检索坑表（[09](docs/09-任务流水线与回测台账.md) 第四节），确认同类任务无已登记的坑
5. 用 `zx-task new` 登记本次任务并关联 Step 与验收文档（09 §八-1；自 Step 1 起不登记即开工视为违规）
6. 开工前向用户复述三件套：**当前 Step、验收标准、本次任务边界**

禁令：

- 禁止旁路"干净区"直接读取原始数据（04 文档关键不变量）
- 禁止口头验收；禁止为自己放宽验收标准
- 文档可起草，**采纳必须用户确认**（05 章程规则 5）
- 发现文档间矛盾：停下，报告用户，不自行裁决

## 六、文档治理（防膨胀）

> 默认判断：**能不写就不写，能加节就不新篇，能归档就不留主地图。**

### 6.1 文档三分法

| 类型 | 例子 | 生命周期 |
|---|---|---|
| 契约型 | 宪章、规范、ADR | 进文档库；ADR 只增不改，其余变更须当场裁决 |
| 状态型 | 路线图进度 | **覆盖更新**，只写当前真相；历史靠 git，正文禁止变更日志 |
| 产出物 | 质量日报、回测报告、session 总结 | **不进文档库**：归档 `${ZX_DATA_ROOT}/reports/`（ADR-0007），不进地图不索引 |

### 6.2 容量硬上限（触发即整理）

- L2a 工作规范 ≤ 6 篇；L2b 产品定义 ≤ 6 篇（每活跃产品一篇）；路由表 ≤ 12 行；单文档 ≤ 300 行；本 README ≤ 150 行
- 触顶想新增 → 三选一：合并进现有文档 / 一进一出替换 / 归档一篇旧的腾位

### 6.3 新信息归属判定树

写任何文字前过树：① 约束/契约 → L2 规范的某一节；② 决策依据 → 新 ADR；③ 当前进度 → 01 路线图（覆盖，不追加）；④ 运行结果/日志/总结 → 数据根 reports/（不是文档）；⑤ 代码行为细节 → 代码注释（不是文档）；⑥ 都不确定 → 不写，先问用户。

**单一事实来源**：同一信息只在一处维护，其他文档引用而非复制。刻意冗余仅限：三大铁律、三目标一句话——防止只读入口者缺上下文。

### 6.4 准入

- 新文档唯一通行证："**它约束什么决策？谁在什么场景必须读它？**" 答不上来 → 不建
- AI agent 禁止主动新建文档，只能提交含上述答案的提议；采纳权在用户
- 新文档必须在第三节地图登记层级、加入第四节路由表、带导航行
- 已登记的未来候选（暂不建，避免空想式文档）：运维 Runbook（系统上线后）、站点信息架构（Step 5 设计时）、财务数据源选型标准（Step 9 开工前，已挂 Step 9 TBD）

### 6.5 修剪（挂在既有节点，不新增流程）

- 每个 Step 验收附带文档健康检查：死链、过期、超容量、**连续 2 个 Step 未被任何路由引用** → 降级 `archive/`
- 归档不删除（退出主地图）；ADR 永不归档
- 文档总数、总行数纳入 Step 验收报告，超限即红

### 6.6 待定项（TBD）约定

- 全库统一用 `TBD` 标记待定点，可全文检索定位
- 文档定稿的判定：TBD 清零，或显式转入该文档的"开放问题"清单

### 6.7 方向演进（目标线是动态的）

- 三目标是**当前方向，不是终身承诺**：可新增（新策略类型）、可扩展（如站点加 MCP 接口）、可下线
- 新增产品/策略 → 新 L2b 文档（过 6.4 准入）+ 路线图目标线 + 宪章范围更新；用户批准
- 现有产品功能扩展 → 更新对应产品文档；触及已定决策（架构/源顺序等）→ 走 ADR
- 产品下线/暂停 → 文档归档（6.5），路线图目标线移除
