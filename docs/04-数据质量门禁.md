# 04 · 数据质量门禁

> **层级**：L2 规范 ｜ **前置阅读**：[02-工程规范](02-工程规范.md) ｜ **何时读我**：接入/审计数据源、调整门禁规则、阅读质量报告时
>
> 地位：**一等公民**（项目宪章铁律 3）。没有门禁的数据源不允许接入；
> 门禁不通过的数据，策略层永远看不到。

## 一、架构（依 ADR-0002）

```
            ┌─────────────┐
 数据源 ──→ │   适配器     │  统一为 Bar/Tick 等标准契约
            └──────┬──────┘
                   ▼
            ┌─────────────┐     违规    ┌──────────────┐
            │  质量门禁    │ ─────────→ │  隔离区        │
            │ (规则引擎)   │             │ (quarantine)  │
            └──────┬──────┘             └──────┬───────┘
                   ▼ 通过                       ▼
            ┌─────────────┐             ┌──────────────┐
            │  干净区      │             │ 每日质量报告   │
            │ (DuckDB)    │             │ + 健康分      │
            └──────┬──────┘             └──────────────┘
                   ▼
            策略 / 分析 / 回测（唯一数据入口）
```

**关键不变量**：策略层、回测层只有"干净区"一个数据入口，代码层面不允许旁路。

## 二、规则目录 v1

处置级别：`REJECT`（该条进隔离区）/ `WARN`（放行但标记计数）/ `FATAL`（整批拒收并报警）

| 编号 | 规则 | 判定 | 级别 |
|---|---|---|---|
| R001 | OHLC 合法性 | `high ≥ max(open,close) ≥ min(open,close) ≥ low` 不成立 | REJECT |
| R002 | 量价非负 | `volume < 0` 或 `amount < 0` 或价格 ≤ 0 | REJECT |
| R003 | 幽灵K线 | `volume = 0` 且当日非停牌（无停牌标记） | WARN |
| R004 | 涨跌幅越界 | 非ST主板 \|涨跌幅\| > 10.5%、ST > 5.5%、创业板/科创板 > 20.5%、北交所 > 30.5%（留 0.5% 容差） | REJECT |
| R005 | 复权因子突变 | 相邻交易日复权因子变化但无分红送转公告对应 | WARN |
| R006 | 交易日历对齐 | 数据日期非交易日，或交易日缺失无说明 | FATAL（整批） |
| R007 | 昨收一致性 | 今日 open/close 与昨收偏差 > 11% 且无除权除息事件 | REJECT |
| R008 | 重复数据 | (symbol, date) 重复入库 | REJECT（后到的） |
| R009 | 时间戳单调 | 分钟/Tick 级时间戳乱序（日线阶段暂不启用） | REJECT |
| R010 | 字段完备性 | 必需字段缺失或为 null | FATAL（整批） |

**规则豁免**（依赖 Step 1 证券主数据，豁免清单配置化）：

- R004/R007 豁免**新股上市无涨跌幅限制期**（注册制下主板/创业板/科创板新股前 5 个交易日）
- R007 阈值与 R004 板块阈值联动，并豁免**长期停牌后复牌首日**（重组等情形的合理跳空）
- 豁免 ≠ 放行不管：豁免条目记 WARN 进日报，供事后复核

规则引擎要求：**新增/调整规则只改配置，不改引擎代码**（Step 1 验收标准 3）。R004 阈值以交易所当期规则为准，配置化维护。

### 实现回填：Step 1c 落地时确定的口径

引擎与谓词已实现（`src/zhixing_quant/quality/`，规则表 `config/gate.toml`）。落地时表里没写、
但必须有个说法的四处，记在这里——它们是口径本身，不是"实现细节"，改任何一条都要连代码一起改：

- **判不了就拒（fail-closed）**：主数据没有该票、日历没装载、字段为 NaN/±inf，都不构成"通过"。
  放行会让"日报一页干净"与"其实什么都没判"长得一模一样（00 宪章第二节的死因）。
  R002 因此也拒 NaN 量价——`NaN < 0` 不成立，但"非负"这件事对 NaN 无从证明。
- **一条数据只记一笔账**：非有限价格归 R001，R002 让路；否则一行脏数据同时挂两条 REJECT，
  健康分被同一件事扣两次，拒收率也再不是"多少行有问题"。
- **R005 现在报"变了多少"，不报"有无公告对应"**：分红送转公告要到 Step 2 才有源可接。
  这正是它配 WARN 而非 REJECT 的理由——它是待核清单，不是结论。
- **R007 阈值按板块联动**（表里的 11% 是主板 10 + 0.5 + 0.5）：写成常数会把创业板 20% 的
  合法跳空整批拒收。`limits_pct` 放在 `[defaults]` 供 R004/R007 共用，是唯一一处真值。
- **新股豁免要求日历覆盖到上市日**：增量抓取只装最近几十天的日历，20 年老票在这份日历上
  "数得出 3 个交易日"，于是被当新股豁免掉 R004——日报上它与正常放行一模一样。
  `listing_day_index()` 数不出来就返回 None，宁可不豁免。

隔离区条目当前是 `(原始 draft, 违规清单)`，只存不修（ADR-0002 第 2 条）；落盘为 Parquet/DuckDB
表在 Step 3 与干净区一起做——Step 1 只交付结构与判定。

## 三、数据源健康分

每个数据源每日打分，100 分起扣：

```
score = 100
      - 40 × REJECT率            （拒收条数 / 总条数，取值 0~1）
      - 20 × WARN率              （取值 0~1）
      - 40 ×（当日有 FATAL ? 1 : 0）
score 下限为 0。
```

| 分数 | 等级 | 处置 |
|---|---|---|
| ≥ 95 | A | 正常使用 |
| 85-95 | B | 关注，周报复盘 |
| 70-85 | C | 降级：仅作交叉校验源，不作主数据源 |
| < 70 | D | 停用，人工介入排查 |

## 四、每日质量报告

Markdown 输出，归档到 `${ZX_DATA_ROOT}/reports/YYYY-MM-DD.md`（数据根见 ADR-0007）：

- 各数据源：总条数、REJECT/WARN/FATAL 计数与明细 Top10、健康分与等级变化
- 隔离区新增条目抽样（人读格式，附原始值与违规规则编号）
- 趋势：近 7 日健康分曲线（文本 sparkline）

### 实现口径（`quality/daily_report.py`，Step 2）

- **明细 Top10 按源各取十条**，不是全市场十条：否则后接入的源会因为老源报错多而从日报上消失。
  每行带源名，级别单独计入键——同一条规则配 warn 与配 reject 是两件事，混在一起数会把告警算进拒收明细。
- **趋势与等级变化读 `reports/scores.csv`**（列 `day,source,total,rejected,warned,fatal,score,grade`），
  不从 Markdown 回读：版式一旦变成解析对象，改一个字就断。分数与等级**都**入流水，
  等级不回推——回推等于把 `report.py` 的分档阈值抄第二份，两处一改就分家。
- 流水按 `(日期, 源)` **覆盖**而非追加：重跑是常态，追加会让同一天在曲线里出现两次，
  看起来只是"那天波动大"。
- "等级变化"对齐的是**流水里最近一条**并打出那个日期，不是"昨日"：周末、停牌、采集失败
  之后的"较昨日"是一个没人验证过的假事实。
- 抽样固定 5 条：一天真错 3000 行时，全量清单会把手要看的那几条埋掉；全量在隔离区（Step 3 落盘后可查）。

## 五、新数据源接入检查清单

任何新源接入前，逐项过：

- [ ] 适配器实现 + pydantic 契约映射
- [ ] 黄金样本（真实响应快照 + 期望解析结果）
- [ ] 规则目录适用性评估（哪些 R 规则启用、阈值是否需源级覆盖）
- [ ] 与现有主源（akshare）抽样交叉对账：随机 20 个 (symbol, date)，OHLC 偏差 < 0.1%
- [ ] 健康分接入日报

### 闲鱼源专项审计（在通用清单之外追加）

> 背景：付费二手数据源，无更新保证，可能是免费源翻录、可能有幸存者偏差。

- [ ] **时间连续性审计**：每只股票逐日扫描，列出所有断档区间（对比交易日历）
- [ ] **幸存者偏差审计**：股票池与交易所全历史名单比对，缺失退市股比例 > 5% 则回测口径必须声明偏差
- [ ] **复权口径识别**：抽样含分红送转的股票，反推其复权方式（前/后/不复权），与声称口径比对
- [ ] **翻录检测**：与 akshare 全量 diff，若 100% 一致则其独立价值为零（谨防花钱买翻录）
- [ ] **入库前冻结原始文件**（只读归档），审计通过前不进干净区

### 抓包源专项（追加）

- [ ] 字段语义逆向对照表（字段名 → 含义 → 验证依据），进文档库
- [ ] 协议版本标记：每次抓取记录 APP 版本，协议变更时黄金样本立刻测红

### 合规自知

抓包源与购买源存在合规风险（APP 用户协议、数据版权不明）。本项目**仅限个人非商业使用**，风险用户已自知并承担。由此导致的源中断/失效，由健康分机制与多源策略兜底（ADR-0004）。
