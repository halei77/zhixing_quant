# 04 · 数据质量门禁

> **层级**：L2 规范 ｜ **前置阅读**：[02-工程规范](02-工程规范.md) ｜ **何时读我**：接入/审计数据源、调整门禁规则、阅读质量报告时
>
> 地位：**一等公民**（项目宪章铁律 3）。没有门禁的数据源不允许接入；
> 门禁不通过的数据，策略层永远看不到。

## 一、架构（依 ADR-0002）

```
            ┌─────────────┐
 数据源 ──→ │   适配器     │  统一为 Bar/Tick 等标准契约
            └──────┬──────┘
                   ▼
            ┌─────────────┐     违规    ┌──────────────┐
            │  质量门禁    │ ─────────→ │  隔离区        │
            │ (规则引擎)   │             │ (quarantine)  │
            └──────┬──────┘             └──────┬───────┘
                   ▼ 通过                       ▼
            ┌─────────────┐             ┌──────────────┐
            │  干净区      │             │ 每日质量报告   │
            │ (DuckDB)    │             │ + 健康分      │
            └──────┬──────┘             └──────────────┘
                   ▼
            策略 / 分析 / 回测（唯一数据入口）
```

**关键不变量**：策略层、回测层只有"干净区"一个数据入口，代码层面不允许旁路。

隔离区已在盘上：`<数据根>/data/quarantine/YYYY-MM-DD.parquet`，一天一个文件、文件名是**运行日**
（ADR-0008）。它存的是"源给了什么、我们为什么不要"，与干净区同一个数据根、不同 dataset，所以
干净区的查询接口天然看不见它——上面那条不变量不因多出一份审计文件而松动。

## 二、规则目录 v1

处置级别：`REJECT`（该条进隔离区）/ `WARN`（放行但标记计数）/ `FATAL`（整批拒收并报警）

| 编号 | 规则 | 判定 | 级别 |
|---|---|---|---|
| R001 | OHLC 合法性 | `high ≥ max(open,close) ≥ min(open,close) ≥ low` 不成立 | REJECT |
| R002 | 量价非负 | `volume < 0` 或 `amount < 0` 或价格 ≤ 0 | REJECT |
| R003 | 幽灵K线 | `volume = 0` 且当日非停牌（无停牌标记） | WARN |
| R004 | 涨跌幅越界 | 非ST主板 \|涨跌幅\| > 10.5%、ST > 5.5%、创业板/科创板 > 20.5%、北交所 > 30.5%（留 0.5% 容差） | REJECT |
| R005 | 复权因子突变 | 相邻交易日复权因子变化但无分红送转公告对应 | WARN |
| R006 | 交易日历对齐 | 数据日期非交易日，或交易日缺失无说明 | FATAL（整批） |
| R007 | 昨收一致性 | 今日 open/close 与昨收偏差 > 11% 且无除权除息事件 | REJECT |
| R008 | 重复数据 | (symbol, date) 重复入库；分钟线是 (symbol, ts)（ADR-0009 决定 3） | REJECT（后到的） |
| R009 | 时间戳单调 | 分钟/Tick 级时间戳乱序（日线阶段暂不启用，分钟阶段启用——ADR-0009 决定 5） | REJECT |
| R010 | 字段完备性 | 必需字段缺失或为 null | FATAL（整批） |

**规则豁免**（依赖 Step 1 证券主数据，豁免清单配置化）：

- R004/R007 豁免**新股上市无涨跌幅限制期**（注册制下主板/创业板/科创板新股前 5 个交易日）
- R007 阈值与 R004 板块阈值联动，并豁免**长期停牌后复牌首日**（重组等情形的合理跳空）
- 豁免 ≠ 放行不管：豁免条目记 WARN 进日报，供事后复核

规则引擎要求：**新增/调整规则只改配置，不改引擎代码**（Step 1 验收标准 3）。R004 阈值以交易所当期规则为准，配置化维护。

### 实现回填：Step 1c 落地时确定的口径

引擎与谓词已实现（`src/zhixing_quant/quality/`，规则表 `config/gate.toml`）。落地时表里没写、
但必须有个说法的四处，记在这里——它们是口径本身，不是"实现细节"，改任何一条都要连代码一起改：

- **判不了就拒（fail-closed）**：主数据没有该票、日历没装载、字段为 NaN/±inf，都不构成"通过"。
  放行会让"日报一页干净"与"其实什么都没判"长得一模一样（00 宪章第二节的死因）。
  R002 因此也拒 NaN 量价——`NaN < 0` 不成立，但"非负"这件事对 NaN 无从证明。
- **一条数据只记一笔账**：非有限价格归 R001，R002 让路；否则一行脏数据同时挂两条 REJECT，
  健康分被同一件事扣两次，拒收率也再不是"多少行有问题"。
- **R005 现在报"变了多少"，不报"有无公告对应"**：分红送转公告要到 Step 2 才有源可接。
  这正是它配 WARN 而非 REJECT 的理由——它是待核清单，不是结论。
- **R007 阈值按板块联动**（表里的 11% 是主板 10 + 0.5 + 0.5）：写成常数会把创业板 20% 的
  合法跳空整批拒收。`limits_pct` 放在 `[defaults]` 供 R004/R007 共用，是唯一一处真值。
- **新股豁免要求日历覆盖到上市日**：增量抓取只装最近几十天的日历，20 年老票在这份日历上
  "数得出 3 个交易日"，于是被当新股豁免掉 R004——日报上它与正常放行一模一样。
  `listing_day_index()` 数不出来就返回 None，宁可不豁免。
- **启用集按粒度配**（ADR-0009 决定 5）：`[[rule]]` 的可选 `grains` 决定一条规则在哪些粒度上跑，
  缺省是全粒度。分钟批只跑 R001/R002/R006/R008/R009/R010：R004 与 R007 的判据是"相对**昨收**"，
  而引擎装配的"上一行"是同批内上一行——在分钟批里那是上一根K线，拿它当昨收会判出一堆假越界；
  R003 在 5 分钟粒度上把冷门票的零成交分钟报成异常，是噪声不是发现；R005 判的东西分钟线不落
  （因子是阶梯函数，日内不变，复权用日线那份）。**代价写在 ADR-0009 后果二**：Step 4a 完成时，
  一批"时间轴完整、价格整体偏移半个百分点"的分钟数据进得了干净区，要等 R011（分钟合成日K 与
  日线对账）才看得见——它已在 Step 4b 就位，见下一节末尾。
- **ST 档取决于 ST 历史，而名单只给"抓取那天挂着帽"**（`sources/akshare/master.py`）：简称前缀
  （`ST` / `*ST` / 老写法 `SST` / `S*ST`）推出的是 `[抓取日, 持续中]` 一段区间，快照日**之前**的行
  仍按非 ST 档判——帽可能是那天之后才戴上的，往前填等于判没有证据的日子。这条上限因此只对
  最近一次抓取负责：戴帽与摘帽都要等下一次重抓才看得见，所以"主数据定期重抓"是判据的一部分，
  不是运维偏好。缺 `golden/manifest.csv` 整批拒收（`zx-daily` 退出码 2），因为"ST 从哪天起算
  判不出来"在日报上与"今天没有 ST 票"一模一样。真 ST 历史（起止日期）要等一个给得出日期的源。

隔离区条目是 `(原始 draft, 违规清单)`，只存不修（ADR-0002 第 2 条）。它的落盘形状有两处**故意**
与干净区相反（ADR-0008 决定 3、4）：**幂等键是整行**——同一个 `(source, symbol, trade_date, rules)`
下原始值不同的两条都留，因为那是两次各自成立的观测，而干净区遇到那种形状抛 `BarConflict`；
**价格列是 `VARCHAR`**——DuckDB 把 Python 侧的 `nan` 绑进 `DOUBLE` 会写成 `NULL`（实测），那会把
"命中 R001"的现场洗成"命中 R010"的现场。干净区的落盘在 Step 3a（存储层）与 3b（每日任务），
隔离区在 Step 3c。

### 表外规则：R011 分钟 ↔ 日线对账（Step 4b，ADR-0009 决定 6）

上面那条"启用集按粒度配"的代价在这里还掉：一批价格整体偏移的分钟数据，逐行判是判不出来的
（每一根自己都合法），只有把它合成日K、再与日线那天比一比才看得见。

它**不在 `[[rule]]` 表里**，而且不是"还没来得及加"：

- 引擎一次只看一批、一个粒度，且按设计不认识存储层（它的注入点只有主数据与日历）。R011 要的
  是**另一个 dataset 的同一天**，那是跨盘的事实。
- 它也不是逐行的：一天 48 根分钟K线合成出一根日K，一条偏差报 48 次等于把拒收率变成"这天的
  K线根数"的函数，§三 那个公式立刻就没法读了。

所以判据住在 `quality/reconcile.py`（纯比较，不碰磁盘），读盘那一半住在 `sources/jobs/minute.py`
（`reconcile_pool`：报告日 × 股票池 × 周期，每组一次比较）。容差不新设：`[defaults]` 的
`tolerance_pct` 与 R004/R007 同一个数，"多少算噪声"全项目只有一处真值。

五种坏法各自一个 `kind`，日报各列各的数：

| `kind` | 判据 | 实测依据 |
|---|---|---|
| `no_minutes` | 日线有成交、分钟一行都没有 | **这就是防断档的那一半**。停一天明天重跑还补得回来，停到滑出 1970 根的窗口就永久没了 |
| `no_daily` | 分钟有一堆、日线那天没有 | 两本账少了一本，多半是日线任务那天漏了这只票 |
| `price` | 开盘或收盘与日线**不相等** | 600519 与 300750，2026-09-11..09-18 实测逐分钱一致 → 写死等号，不等就是有一边错 |
| `extremes` | 分钟最高价越过日线最高价、或最低价跌破日线最低价 | 反方向（合成值落在日线区间内）是常态：日内瞬时极值分钟聚合看不见 |
| `volume` | 量或额的相对偏差超过 `tolerance_pct` | 实测合成量比日线少 0%~-0.21%（尾差来自收盘集合竞价）→ 留容差，写等号的规则每天都在拒真数据 |

三条不写进表却同样属于口径的决定：

- **两边都读不复权价**。因子只挂在日线上，复权一遍等于把同一个因子只乘到一本账上，那偏差比它
  要抓的任何一种都大。
- **全天停牌那天不报 `no_minutes`**。那种日子真的没有分钟行，而源的停牌标记不可靠，所以
  "日线 `volume = 0`"也认。代价是"零成交而源在漏票"会被放过——每天几十条假警报会淹掉真断档。
- **它不进 §三 的健康分，也不报警**。分钟线是唯一的分钟数据源，没有第二个源来仲裁差异，
  把对不上折算成拒收率等于把 R011 变成对自己管道的评分；而"几条断档算多"需要几天的日报做基线，
  凭感觉定阈值的结果是要么天天响、要么永不响。这条线等实测数据攒够再回来定（Step 4 验收 2 只要求
  "覆盖率与偏差进日报"，那一节在 `reports/minute/<报告日>.md`）。

## 三、数据源健康分

每个数据源每日打分，100 分起扣：

```
score = 100
      - 40 × REJECT率            （拒收条数 / 总条数，取值 0~1）
      - 20 × WARN率              （取值 0~1）
      - 40 ×（当日有 FATAL ? 1 : 0）
score 下限为 0。
```

| 分数 | 等级 | 处置 |
|---|---|---|
| ≥ 95 | A | 正常使用 |
| 85-95 | B | 关注，周报复盘 |
| 70-85 | C | 降级：仅作交叉校验源，不作主数据源 |
| < 70 | D | 停用，人工介入排查 |

## 四、每日质量报告

Markdown 输出，归档到 `${ZX_DATA_ROOT}/reports/YYYY-MM-DD.md`（数据根见 ADR-0007）：

- 各数据源：总条数、REJECT/WARN/FATAL 计数与明细 Top10、健康分与等级变化
- 隔离区新增条目抽样（人读格式，附原始值与违规规则编号）
- 趋势：近 7 日健康分曲线（文本 sparkline）

### 实现口径（`quality/daily_report.py`，Step 2）

- **明细 Top10 按源各取十条**，不是全市场十条：否则后接入的源会因为老源报错多而从日报上消失。
  每行带源名，级别单独计入键——同一条规则配 warn 与配 reject 是两件事，混在一起数会把告警算进拒收明细。
- **趋势与等级变化读 `reports/scores.csv`**（列 `day,source,total,rejected,warned,fatal,score,grade`），
  不从 Markdown 回读：版式一旦变成解析对象，改一个字就断。分数与等级**都**入流水，
  等级不回推——回推等于把 `report.py` 的分档阈值抄第二份，两处一改就分家。
- 流水按 `(日期, 源)` **覆盖**而非追加：重跑是常态，追加会让同一天在曲线里出现两次，
  看起来只是"那天波动大"。
- "等级变化"对齐的是**流水里最近一条**并打出那个日期，不是"昨日"：周末、停牌、采集失败
  之后的"较昨日"是一个没人验证过的假事实。
- 抽样固定 5 条：一天真错 3000 行时，全量清单会把手要看的那几条埋掉；全量在隔离区，
  按运行日一个 Parquet 文件（ADR-0008）。
- "等级变化"那行打的是**完整日期**（`2024-01-12`）：流水能存到任何一天，`01-12` 隔了一年就会
  被读成"上个月"。曲线下面那行紧凑的 `MM-DD` 不展开，是为了与 sparkline 一格一格对齐。
- **"进干净区"那句落在首行下面**（Step 3b，取自 `storage.write.WriteReport`）：判成多少行说的
  是门禁要不要这些数据，落进盘多少行说的才是"明天有没有数据可用"。两个数只在磁盘写满或
  落盘接错线那天才会分开，而那天恰恰最需要看见它们不一样。重跑时这行写成「+0 行、已是最新」
  ——幂等的正常状态若显示成一个孤零零的 0，第二天就有人来查磁盘。
- **"隔离区"那行紧跟在它后面**（Step 3c，取自 `storage.quarantine.QuarantineReport`）：它报的是
  **这次运行**的账，而上面三张表报的是**那一天**的行——两日批里上一日那几行也进了这次运行的文件，
  裁到报告日的只有表。三种句式说三种情况：「新记 1/2 条」= 交来两条、盘上真多了一条（同批重复的
  那条不记第二遍）；「N 条重跑前就已在盘上」= 幂等，连文件都没动；句尾始终带路径，否则本节开头那句
  "全量可查"就还只是一个概念。抽样那句因此说"报告日没有拒收行"而不是"今天没有"——坏数据在上一日时，
  首行的账与抽样清单会一个有数一个空，两句都得说自己的那条日期。FATAL 整批不落隔离区（ADR-0008
  决定 6），所以这行为 0 有两种含义：
  今天没拒收，或今天根本没读出行——后者由告警与退出码说，不由这行说。
- **"没判成的票"那一节把原因分成三种**（`sources/jobs/daily.py`，Step 2 起）：抓取失败（查网络与
  限流）、抓取成功但当日无行（查那只票是否停牌，或源在漏票）、熔断后没再抓取（源整体不行）。
  处置方向不同，合成一句"失败 N 只"就有人会去查错的地方；三者都不计入日报的分母，所以缺票不会
  让健康分"变好"。**"当日无行"的票不交给门禁**：批级结果按源打分（§三），而零行的批次在引擎里
  只能推断出一个 `source=""` 的无名源外加 R006 的整批 FATAL——4430 只里停牌两只就把
  `akshare_daily` 打成 D，而停牌不是源的错。它记在清单上、不记在分数上；整池皆空仍由
  `DayResult.ok` 拦下（退出码 1），源在给空表照样响。
- **出口是 `zx-daily`**（`sources/jobs/cli.py`）：打印日报到标准输出并以退出码报成败——
  `0` 判成、`1` 一只都没判成、`2` 快照缺失/日历判不出（本地环境问题，与"源不行"分开）。
  报告与 `reports/`、`scores.csv` 一律落数据根（ADR-0007）。定时器不自动装（05 Q1）。
- **分钟日报另落 `reports/minute/<报告日>.md`**（`zx-minute`，Step 4）：归档名是报告日，与日线同目录
  等于每天互相覆盖一份，而两份说的是两件不同的事。它的最后一节是 R011（见 §二 末尾）：先一行
  「查了 N 组（票 × 周期）」，再按 `kind` 计数，然后**每类各列三条**——全局截断会让一百条断档把
  一条价差挤出日报。没给对账边界时那一节写「这次没查」：把没做报成"五种坏法全 0"是日报最坏的假。

## 五、新数据源接入检查清单

任何新源接入前，逐项过：

- [ ] 适配器实现 + pydantic 契约映射
- [ ] 黄金样本（真实响应快照 + 期望解析结果）
- [ ] 规则目录适用性评估（哪些 R 规则启用、阈值是否需源级覆盖）
- [ ] 与现有主源（akshare）抽样交叉对账：随机 20 个 (symbol, date)，OHLC 偏差 < 0.1%
- [ ] 健康分接入日报

### 闲鱼源专项审计（在通用清单之外追加）

> 背景：付费二手数据源，无更新保证，可能是免费源翻录、可能有幸存者偏差。

- [ ] **时间连续性审计**：每只股票逐日扫描，列出所有断档区间（对比交易日历）
- [ ] **幸存者偏差审计**：股票池与交易所全历史名单比对，缺失退市股比例 > 5% 则回测口径必须声明偏差
- [ ] **复权口径识别**：抽样含分红送转的股票，反推其复权方式（前/后/不复权），与声称口径比对
- [ ] **翻录检测**：与 akshare 全量 diff，若 100% 一致则其独立价值为零（谨防花钱买翻录）
- [ ] **入库前冻结原始文件**（只读归档），审计通过前不进干净区

### 抓包源专项（追加）

- [ ] 字段语义逆向对照表（字段名 → 含义 → 验证依据），进文档库
