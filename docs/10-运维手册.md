## 二、服务与开机自启

| 服务 | 位置 | 内容 |
|---|---|---|
| `zhixing-site` | 服务器 systemd | `uv run --frozen zx-site`，绑 127.0.0.1:8000；`EnvironmentFile=/opt/zhixing_secrets/site.env` |
| `caddy` | 服务器 systemd | HTTPS 反代 443→8000，证书自动签续 |

**重部署（代码更新）**：rsync 仓库（排除 `.git/.venv/data/golden/缓存`）→ `uv sync --frozen` → `systemctl restart zhixing-site`。静态件有 `Cache-Control: no-cache`（2026-09-23 起），浏览器不会再拿旧 JS。

**数据采集与发布**：`tools/daily_pipeline.sh`（本机）——先 `zx-daily` 全市场日线 + `zx-minute --periods 60` 全市场 60 分（[ADR-0021](adr/0021-分钟线采集范围.md) 决定 3：漏抓即永久缺失，每日必采），再 `tools/publish_site.sh` rsync 干净区**行情 dataset + ADR-0015 六张参考表**（daily_basic/forecast/stk_limit/fina_audit/stk_holdernumber/index_daily，缺目录的跳过）+ 主数据快照到服务器；工作日 17:00 cron 自动跑（WSL2 cron 常驻前提；家里机器不保证 7×24 是 ADR-0006 明示代价）。日志 `reports/daily_pipeline.log`（采集与发布共用，末行记 `rc_collect`/`rc_minute`/`rc_publish`）。

**交付口径（1 分钟K 的年窗截断）**：`minute_1` 只发**最近两个自然年**的 `year=*` 分区，`--delete` 清掉更老的（`publish_site.sh` 自动按 `date +%Y`−1 算保留线）。理由：服务器 40G 盘、实测空闲 34G，而 `minute_1` 全市场外推 **12.4 GB/年**——发全历史 5 年约 63 GB，第 3 个自然年就爆盘。两年窗峰值约 25 GB。**全历史留在家里**（ADR-0006：重计算在家、云只服务站点）；站点模板对 1 分钟最深只要 30 天（`site/api` 的天数封顶）。要查全历史回家里跑。发布后健康检查会一并打**磁盘余量**——只 curl 200 只证明进程活着，盘满了它照样 200 然后明天写不进去。

- 之所以串成一条而不是两条 cron：发布必须发生在采集之后，而采集时长随源波动（全市场数千只票，慢时几十分钟），两条 cron 之间的固定间隔迟早被某天的慢源吃掉。采集失败（退出码非 0）**不阻断**发布——干净区已有的数据照发，站点不因源挂而停更。
- 手动只发数据不采集：直接跑 `tools/publish_site.sh`。

## 三、数据流与新鲜度

```
zx-daily / zx-minute / zx-relay（WSL2，门禁后入干净区）
  → tools/daily_pipeline.sh（工作日 17:00 cron：先采集再发布）
  → 服务器 /opt/zhixing_data → 站点读副本
```

- "站点数据为什么旧"先查三处：本机采集当天跑没跑（`reports/daily_pipeline.log` 的 `rc_collect`/`rc_minute`）→ 发布日志有无报错 → 服务器 `systemctl is-active zhixing-site`。
- 回填类操作跑完后**手动发布一次**，不等 cron。三条回填入口：
  `zx-daily --previous-days`（日线补历史）、`zx-minute --symbols`（分钟补漏抓的尾巴）、
  `zx-relay backfill --table daily_basic|forecast|stk_limit [--relay rds|promax] [--symbols …] [--limit N]`
  （参考表**可续跑**回填，任务 #53）——它按**读盘**判缺口（日线有量的交易日 − 参考表已有），
  不靠 /tmp 运行件；重跑零请求、同键同值零改写，中断后接着跑不丢已成的盘。
  报告落 `reports/relay/<日>/`。注意 `pull --table index_daily` 当前会 AttributeError
  （锚点定义缺失，见决策包 #9），回填侧已 fail-closed 只收三张表。

## 四、转接源运行要点（ADR-0014/0015 的运维侧）

- key：`~/.zhixing_secrets/{rds,promax}.key`（600）；失效表现 = zx-relay 退出 2 话术"没开始"。
- **rds 单次查询 5000 行静默截断**（响应照给 count/has_more）——全市场拉取不可用，逐票（`--symbols`）绕开；截断由 has_more 硬响，不会无声丢行。
- **promax 不认 limit/offset**（一次全吐）但有间歇 503 `upstream_pool_exhausted`（几分钟自愈）——回填驱动对它用短退避 + 跳日续跑，失败日改天重跑即可（幂等）。
- 除权日的涨跌停板价对原始昨收必然"超阈"，装载器以两界反推参考价自洽校验放行并在报告点名待核。

## 五、已知形态与排障入口

| 现象 | 结论 | 入口 |
|---|---|---|
| 页面中文变方块 | 终端/截图环境缺 CJK 字体，站点字节与响应头均 UTF-8 | `curl -sI`（站点）看 charset |
| 切模板没反应 | 2026-09-23 前的浏览器缓存旧 JS——现已 no-cache，强刷一次即可 | 控制台看 app.js 行号对不对得上 |
| 科创板/北交所搜得到但K线空 | 该票日线在回填批次里缺失 | `zx-daily --symbols <票> --previous-days N` 后手动发布 |
| 工作日 17:00 后站点数据没更新 | 看 `reports/daily_pipeline.log` 末行的 `rc_collect`/`rc_minute`/`rc_publish`：非 0 是采集或发布失败；日志为空/停在 start 是采集还在跑或卡住 | 该日志；`crontab -l` 确认 `daily_pipeline.sh` 那行在 |
| 长窗口回测日报健康分 D | R006 对 700 日窗口的停牌断档 fatal，行级拒收不连坐 | 日报违规明细；单日窗口的日常采集不受影响 |
| 备份 | **仍无有效备份**（O1，任务 #32：`ZX_BACKUP_ROOT` 待用户配真实网盘目录） | ADR-0005 |

## 六、变更规则

服务器上的服务拓扑、域名、发布链路变更 = 改本手册 + 视情况新 ADR（ADR-0006 的变更走新 ADR）。本手册只记"现在是什么样"，为什么这样部署去 ADR-0006/0014/0015/0016/0017 查。
