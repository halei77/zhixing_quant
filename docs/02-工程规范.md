## 二、完成定义（DoD）

一个任务**同时满足**以下全部条件才算完成：

1. ✅ 文档/契约已更新（涉及行为变更时）
2. ✅ `ruff check` 零警告
3. ✅ `mypy --strict` 零错误
4. ✅ `pytest` 全绿，新增逻辑有对应测试
5. ✅ 覆盖率门禁通过（核心模块 `quality`/`backtest`/`strategy`/`tasks` ≥ 90%，整体 ≥ 80%，CI 自动判定；清单变更需用户批准）
   - **生效时点**（用户决议 2026-09-18）：阈值对某模块**首次出现被测代码的那个 Step** 起生效；Step 0b 的空骨架不比对阈值，否则与 Step 0 验收标准 1「空项目 CI 全绿」互斥
   - 但 0b 必须**证明这条门禁真的会拦**：CI 附带一个自测，用故意的低覆盖假模块验证阈值判定会测红——与 Step 0 验收标准 2「故意提交类型错误要被拦截」同一手法。门禁没被证明有效，就等于没有门禁
   - 阈值数字单一来源在 `pyproject.toml`，本文只记口径；调阈值需用户批准
6. ✅ 涉及策略/回测：L4 测试（确定性 + 截断一致性）通过
7. ✅ 涉及数据源适配器：黄金样本测试存在且通过

**任何 agent 或人声称"完成"但 CI 未全绿 = 未完成。无例外。**

## 三、CI 门禁流水线

每次提交触发，顺序执行，任一失败即红：

```
ruff check → mypy --strict → pytest（含覆盖率判定）→ 契约/黄金样本测试
```

- **main 的不变量是 CI 绿，不是 PR**：允许直推 main，但推送前本文第三节的门禁必须在本地全绿；推完 CI 转红即视为事故，当场修复或回滚，不许挂着红继续推进
- 不允许 `pytest.skip` / `xfail` 静默堆积：每个 skip 必须关联 issue 编号

## 四、提交规范

- Conventional Commits：`feat:` / `fix:` / `test:` / `docs:` / `refactor:` / `chore:`
- 一个提交只做一件事；测试与实现同提交
- 提交信息写"为什么"，不写"做了什么"（diff 自己会说话）
- **密钥/Token/凭据禁止入库**：`.env` + `.gitignore`，仓库只放 `.env.example` 样例

## 五、分支模型

- `main`：永远可发布，CI 常绿
- 功能分支：`feat/xxx`、`fix/xxx`，短生命周期（≤ 3 天），完成即合即删
- **PR 不强制**（用户决议 2026-09-18）：单人项目以直推 main 为准，想留独立评审记录时才开 PR；门禁强度由第三节 CI 承担，不靠 PR 这道手续
- 评审留痕不依赖 PR 描述：05 规则 3 的对抗评审触发点是**事件**（适配器/引擎完成、策略合入 main 前），留痕载体是 09 的 `task_events`
- **推送授权（用户决议 2026-09-18）**：agent 本地提交通过门禁后可直推 `origin/main`，不必逐次确认。仍然必须先问的动作：`push --force`、推非 main 分支到远端、`reset --hard`、删分支、放宽任何测试口径（05 Q3）

### 仓库外的数据根（不入 git）

代码仓库之外还有一个数据根，放 Parquet / 质量日报 / 回测产物 / 任务库；位置与布局的决策依据见 [ADR-0007](adr/0007-数据存储位置.md)。

- 配置项 `ZX_DATA_ROOT`，默认 `/home/lei/zhixing_data/`，子目录 `data/`、`reports/`、`backtests/`、`taskdb/`、`golden/`、`site/`
- **备份根是第二个配置项** `ZX_BACKUP_ROOT`（[ADR-0005 补充决定一](adr/0005-备份与灾难恢复.md)）：它**没有默认值**，没配就不运行。它是全仓第二个"绝对路径的落点"，因而与 `ZX_DATA_ROOT` 同受本条约束——备份代码里不许出现盘符，也不许与数据根套在一起
- `golden/` 是 ADR-0007 布局之后补的一项：真实响应快照（`tools/capture_golden.py` 抓的 CSV）先落这里，用户批准后才作为测试资产进仓 `tests/golden/`（05 Q1-③）。两处隔开，才分得清"抓下来的"和"认过的"
- 代码取路径**只能**从这个配置读；禁止模块自行拼 Windows 盘符或硬编码绝对路径
- 对应检查：`tests/test_path_hygiene.py` 扫 `src/`、`tests/`、`.github/`、`pyproject.toml`、`.pre-commit-config.yaml`，出现盘符、`/home/`、`/mnt/` 字面量即测红
- 唯一豁免点就是数据根配置文件本身（默认值总得写死在那里），按**仓库相对路径**精确列入 `EXEMPT`；禁止按文件名豁免或放宽正则——该文件末尾有自检测试盯着这两种拆法

## 七、文档来源

- **仓库 `docs/` 是契约的唯一来源**（Step 0c 决议，2026-09-18，取代此前"zx_docs 编辑、docs 发布"的双份设想）：文档改动与受它约束的代码改动进同一个 commit，原子生效
- 取消平行副本的理由：`zx_docs` 在本机实测不存在（0b 期间全盘查过），双份只是把 ADR-0005 背景那次灾难换成慢性的"代码已改、文档还旧"漂移；文档驱动的前提是文档与代码同步演化，而不是文档有个更舒服的编辑处
- 完整性由 `tests/test_docs.py` 机器保证（死链、未登记文档、缺导航行、README 链接前缀、容量上限）。没有第二份，也就没有"同步"这个动作
- 确需在别处改（手机等）：走远端分支或 issue 回流，不允许长期平行副本。变更本节需新建 ADR
