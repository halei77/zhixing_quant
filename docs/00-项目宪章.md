# 00 · 项目宪章

> **层级**：L1 纲领 ｜ **前置阅读**：无（从 [README](../README.md) 进入）｜ **何时读我**：首次接触项目；判断"该不该做某件事"时

## 一、愿景

做一个**个人级 A 股行情与量化研究平台**，核心追求三句话：

- **干净的数据** —— 任何策略、任何分析，只接触经过质量门禁的数据。
- **可信的回测** —— 结果可复现，未来函数有机器测试兜底，不自欺。
- **可维护的系统** —— 一个人能长期维护得动，不再重蹈"维护心累而放弃"。

## 二、上一版失败教训（立此存照）

| # | 教训 | 本次对策 |
|---|---|---|
| 1 | 脏数据直接进策略层，每个脏点都变成一次"信号异常"，排查成本指数级 | 数据质量门禁为独立层，策略只读干净区（ADR-0002） |
| 2 | 范围一次摊太大：站点 + 服务 + 双策略 + 多数据源，维护成本相乘 | 范围纪律（本文第四节），一次只推进一个 Step |
| 3 | 3 个 agent 宽松并行、无机器可执行的验收标准，低级错误泛滥 | 单主线 + CI 机器验收（05-AI协作章程、02-工程规范） |

## 三、三大铁律

1. **文档驱动**：先契约后实现。文档与代码冲突时必须当场裁决，不留"以后再说"。
2. **机器验收**："完成"的唯一判据是 CI 全绿（类型检查、测试、契约校验、覆盖率门禁）。任何人或 AI 口头说"做完了"均不算数；所有任务经任务流水线逐阶段留痕（见 [09](09-任务流水线与回测台账.md)）。
3. **数据质量门禁是一等公民**：没有门禁的数据源不允许接入；没有黄金样本的适配器不允许合入。

## 四、范围纪律

> 目标线是**当前方向，不是终身承诺**：可新增、可扩展、可下线，演进流程见 README 6.7。

### 做（当前阶段）

- 市场：**仅 A 股**
- 产品形态：**目标 1 = 提示词生成站点**（轻量 Web，自用，部署阿里云；定义见 [06](06-产品定义-提示词站点.md)）
- 数据粒度：日K + 分钟K（5/30/60 分，目标 1 与目标 2 均需要）
- **目标 2 = 日内做T 信号系统**（持仓 ≤10 票盯盘，iOS 推送买卖点，只出信号不自动下单；定义见 [07](07-产品定义-日内做T.md)）
- 目标 3 = 价值回归策略（情绪超跌+基本面未受损的分等级介入点，每日盘后市场扫描出池；数据需求最重，最后做；定义见 [08](08-产品定义-价值回归.md)）

### 不做（直到解锁条件达成）

| 不做项 | 解锁条件 |
|---|---|
| 自动下单/实盘对接 | 无计划——系统只出信号；如需变更必须新 ADR + 人工评审 |
| 重型行情站点（实时推送/复杂图表/多用户） | 有明确展示需求时；目标 1 的轻量站点不受此限 |
| 分布式存储/计算 | 单机 DuckDB 出现明确性能瓶颈（ADR-0003 载明阈值） |

## 五、本阶段成功标准

1. 数据门禁连续 30 天自动运行，每日产出质量报告。
2. 每个数据源有健康分，脏数据来源可追溯、可量化。
3. 目标 1 一期站点上线并进入日常使用（生成的提示词被真实用于 LLM 分析）。
4. 目标 2 信号系统只有通过启用门槛（含模拟信号期验证）才投入使用；未通过则诚实停用——"不如不用"是合法结论。
5. 回测结果 100% 可复现；防未来函数测试（L4）全绿。
