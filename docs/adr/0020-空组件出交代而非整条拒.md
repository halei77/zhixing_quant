# ADR-0020 · 空组件出交代，不整条拒生成

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0011](0011-提示词组装的口径.md)、[ADR-0016](0016-估值组件进提示词的口径.md)、[06-产品定义-提示词站点](../06-产品定义-提示词站点.md) ｜ **何时读我**：改提示词组装的空数据行为、往模板里加组件、或有人提议"某个组件没数就该整条拒"时（变更须新建 ADR）

- 状态：Accepted（2026-09-24，用户指令"你看着处理"；代码与测试先落地，本 ADR 事后补记口径）
- 决策人：用户委托 agent 裁决
- 关联：ADR-0011 决定 5（换手率缺分母仍整条拒，**不**被本 ADR 取代）、ADR-0016（参考表空表）、`table.IncompleteComponent`、`compose.EmptyPrompt`

## 背景

`table.render` 有一条 fail-closed：`if not bars: raise IncompleteComponent("一张都没有的K线表
不进提示词：那是组件没取到数，不是没有涨跌")`。原顾虑成立且重要——**空表会被大模型读成
"那天没涨跌"**，比缺数据更坏。实现于是把它落成"任一组件空 → 整条拒生成"。

2026-09-24 用户报"中际旭创没数据"，实测翻出来这个形状的真实代价：

| 探针 | 300308 结果 |
|---|---|
| `/api/search?q=中际旭创` | ✅ 命中（三路都能） |
| `/api/kline?code=300308` | ✅ 701 天日K（2023-11-06 起） |
| `/api/prompt` 短期投资 | ❌ 400「一张都没有的K线表不进提示词」 |

根因不在数据在不在，在**默认模板吃四段数据、其中 minute_60/30/5 全空**（分钟线只采了采集
池那几只，[ADR-0021](0021-分钟线采集范围.md) 定范围）。全市场 5565 只票里只有那几只有
`minute_*`——"任一组件空就整条拒"等于**把默认模板按死在个位数票上**，而报错既不点名缺哪
一段，前端还把正文清成「选一只票，点生成。」。

同一现场还翻出一个同族的漏：`render_valuation` / `render_forecast` 空行时**不抛**，会交出
一张**只有表头的空表**——正是 `IncompleteComponent` 那条原顾虑要防的东西，只是它没拦到。

## 决定

### 决定 1：空组件出一节「本节无数据」交代，不给空表

- 模板的某个组件在查询区间里**一行都没有** → 那一节仍然出现在提示词里，小标题照旧用
  `heading(selection, 0)` 承认「盘上 0 个交易日，模板要 N」，正文是固定的 `NO_DATA_NOTE`
  （点名"是组件没取到数，不是没有变化"，并要求模型按反幻觉第 3 条写「数据未提供」）。
- **空表任何形式都不给出**：没有表头骨架、没有数据行、没有 `|`。原顾虑原样有效，只是处置
  从"拒掉整条"改成"出一节交代"。
- K线、`daily_basic`/估值参考表、`forecast` 事件表**同一条线**：空了都出交代，不交只有
  表头的空表（这一条顺带堵掉上面那个漏）。

### 决定 2：每个组件都空 → 照旧整条拒

- 模板要求的**每一段**都一行没有时，仍然 `raise table.IncompleteComponent`，消息沿用原句
  「一张都没有的K线表不进提示词：那是组件没取到数，不是没有涨跌」。
- 理由：一份数字都没有的提示词，正是 06 §一 要防的"指令齐全、数字全靠编"。`compose.EmptyPrompt`
  （"一份数据都没拿到就不生成"）是同一条线的另一半，不改。
- 判据是**有数的组件个数 `with_data`**，不是 sections 个数——交代段不算数。

### 决定 3：A11y 与外壳的连带约定

- 生成失败（含决定 2 的拒）时，**原因必须留在正文区**（`data-testid="prompt-body"`），
  不许只在 toast 上闪一下就没了；成功时正文区照常是提示词。
- 反幻觉固定头部**只有一份**（`compose.ANTI_HALLUCINATION`），交代段不许再补一份。

## 代价

- **代价一：提示词可能"缺一段"**。模型拿到的是不完整的数据组合，回答「短期投资」这种
  明确吃分钟K 的问题时会弱于全数据。缓解：交代段点名缺什么，模型按反幻觉第 3 条写
  「数据未提供」而不是编——这比"整条拒、用户什么都拿不到"更接近 06 §一 的定位。
- **代价二：缺口从"报错"降级成"提示词里的一句话"**，用户更容易漏看。缓解：小标题自己承认
  「盘上 0 个交易日」，不是静默少行。
- **代价三：模板作者可能误以为"空了也没事"**。缓解：本 ADR 与 `prompt.build` docstring
  写明边界；**缺分母（换手率）仍整条拒**（ADR-0011 决定 5 不被本 ADR 放宽）——那是"装
  得出、跑不得"，与"没数"不是一回事。

## 不做什么

- **不放宽 ADR-0011 决定 5**：换手率缺流通股本仍 `IncompleteComponent`，整条拒。
- **不在壳里推断哪个组件会有数**（docs/11 §六-2 壳不产生口径）：数据在不在只由服务端说。
- **不静默砍天数**：`days` 取不到就是取不到，标题承认，表里不多装（ADR-0012 决定 3 原样）。

## 回归条件

下列任一成立 → 新建 ADR 取代本 ADR：

1. 模板有了"组件级必选/可选"的声明（那时"空了就交代"应改读模板声明，而不是一律交代）
2. 大模型实测被交代段带偏（写出它不该写的结论），证成代价一比预估重
3. 采集范围补齐到全市场（[ADR-0021](0021-分钟线采集范围.md)）后，缺口极少见，改为"空就
   整条拒 + 明确报错"在体验上更利落
