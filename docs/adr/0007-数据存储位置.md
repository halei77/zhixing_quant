# ADR-0007 · 数据存储位置（E 盘 → WSL 原生目录）

## 背景

ADR-0003 的决策依据写着「机器情况：E 盘 3.7T 空闲」。2026-09-18 实际核查：这台 WSL2 只挂载了 `C`，PowerShell `Get-PSDrive` 也只返回 C —— **E 盘不存在**。0003/0005/0006 与 01/04/09/README 里的 `E:\zhixing_quant\...` 全部无法落地。用户决议：代码与数据都在 WSL 内，不依赖 Windows 盘符。

## 候选方案

| 方案 | 评价 |
|---|---|
| **A. WSL 原生 ext4 `~/zhixing_data/`** | ✅ 本地块设备，随机读性能好；与 git 工作区分离，数据不可能被误提交 |
| B. `/mnt/c/zhixing_data/` | ❌ 走 9p 跨系统协议，IO 慢一个量级，直接威胁 Step 3 验收标准 1「单票历史查询 < 100ms」 |
| C. 另接物理盘 | 当前不可得；将来加盘按本 ADR 决定 4 只改配置值 |

## 决定

1. **数据根目录** `ZX_DATA_ROOT = /home/lei/zhixing_data/`，与代码仓库同级但独立于 git 工作区
2. 目录布局：`data/`（Parquet，沿用 0003 的 `year=YYYY/symbol=...` 分区）、`reports/`（04 质量日报）、`backtests/`（09 回测产物）、`taskdb/`（09 任务流水线库）
3. **路径单一来源**：代码一律读配置项取数据根（配置项定义见 02 §六），禁止任何模块自行拼盘符或硬编码绝对路径
4. 换盘 / 换机器 / 迁移到独立挂载点 = 改一个配置值，不改代码

## 后果

- 正面：分析型 IO 落在原生 ext4；数据与代码物理分离，`git status` 永远不会冒出数据文件
- **容量前提变弱，这是本 ADR 的代价**：可用空间从 3.7T 降到 951G。日线（压缩后数十 GB 级）无压力；但 0003 自述分钟线约为日线 50 倍体量，全市场多年分钟线可能吃掉数百 GB → **Step 4 的回填范围与起点必须按 951G 重算**，不得沿用 3.7T 时代的"随便存"假设。WSL 虚拟磁盘扩容属 Windows 侧运维事项，届时补进运维 Runbook（README §6.4 已登记该未来候选）
- 备份（ADR-0005）语义不变：备份对象由「E 盘数据」改读为「`ZX_DATA_ROOT` 全部内容 + git 仓库 + 任务流水线库」，网盘介质、每日 02:00 增量、每周日全量、保留 3 代全量均不变
- 文档同步：01/04/09/README 的 E 盘字样随本 ADR 一并更正；三份旧 ADR 原文按「ADR 只增不改」保持不动，其位置条款以本文件为准
