# ADR-0004 · 数据源接入顺序

> **层级**：L3 决策档案 ｜ **前置阅读**：[04-数据质量门禁](../04-数据质量门禁.md) 第五节 ｜ **何时读我**：想调整数据源接入顺序时（变更须新建 ADR）

- 状态：Accepted（2026-09-17）

## 背景

计划接入三类数据源，风险特征差异极大：

| 源 | 成本 | 风险 |
|---|---|---|
| akshare | 免费 | 中（接口偶发变动，社区维护） |
| APP 抓包 | 免费但维护重 | 高（APP 升级协议即变，字段无语义） |
| 闲鱼购买 | 付费 | 高（可能翻录、幸存者偏差、口径不明、无更新保证） |

## 决定

**接入顺序：akshare → 抓包源 → 闲鱼源。** 每个源的接入以前一个源稳定运行为前提。

1. **akshare 先行**（Step 2）：零成本、覆盖全，用于把"适配器 → 门禁 → 报告"全链路跑稳，并作为后续所有源的**交叉校验基准**
2. **抓包源次之**：价值在于提供 akshare 没有的字段（视逆向结果而定）；黄金样本 + 协议版本标记专门防"APP 升级悄悄变协议"（04 文档第五节）
3. **闲鱼源最后**：接入前必须通过专项审计（时间连续性、幸存者偏差、复权口径、翻录检测），审计工具依赖前两个源就位（04 文档第五节）

## 理由

- 门禁体系必须先在低风险源上练熟，再迎接高风险源——顺序反了等于用脏源检验门禁，两头都不可信
- 闲鱼源的审计（尤其翻录检测、复权口径识别）需要一个可信基准源（akshare）做 diff，所以它必须最后

## 后果

- 正面：任何时刻系统中最多只有一个"未驯服"的新源，爆炸半径可控
- 负面：想用的抓包/闲鱼数据要等；接受——慢而稳是本项目既定节奏
