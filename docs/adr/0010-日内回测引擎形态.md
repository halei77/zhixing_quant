# ADR-0010 · 日内回测引擎：时钟、成交现实与底仓台账

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0009](0009-分钟线源与存储布局.md)、[ADR-0002](0002-数据质量门禁架构.md)、[07 §五](../07-产品定义-日内做T.md)、[03 §二 L4](../03-测试策略.md) ｜ **何时读我**：写或改 `backtest/` 任何一块之前；要回答"这笔单为什么算成交/不算"时（变更须新建 ADR）

## 背景

分钟线已经在盘上（Step 4），`Bar` 有 `ts`（ADR-0009 决定 2），查询接口只有一处换算口径
（ADR-0009 决定 4）。缺的是把"信号"变成"这笔到底成没成交、成交价多少、盈亏多少"的那台机器。

难处不在代码量，在于**分钟K线只有四个价一个量**（`open/high/low/close/volume/amount`），任何
关于"成交在哪"的说法都必须只靠这六格支撑得住。上一版项目的死因是"看起来合理"的假设（00 宪章
第二节），而回测里最典型的"看起来合理"就是**用信号价成交**——07 §5.2 把它列为禁止项，本 ADR
的全部成交判据都是为它准备的替代物。

第二处难：T+1、涨跌停、停牌是**制度**，不是统计量。它们必须写成"能不能成交"的硬判定，而不能
写成"成交概率打折"的软参数——软参数会让回测收益与制度无关，改一个数字就多赚一点。

## 候选方案

| 方案 | 评价 |
|---|---|
| **A. 事件驱动，逐根K线；成交在 `delay_bars` 之后那根的开盘价** | ✅ 唯一能同时满足 07 §5.2（禁信号价成交、延迟参数化）与 03-4.2（截断一致性）的形态 |
| B. 日线向量化引擎复用 | ❌ 07 §5.1 明说两种引擎不可混用。向量化里没有"这一根买不到"的位置：整段 numpy 算出来的仓位无法拒绝某一笔成交 |
| C. 用信号所在那根的收盘价成交 | ❌ 07 §5.2 禁止。收盘价是"这根K线走完才知道"的事实，拿它成交等于让策略穿越 1–59 秒到 5 分钟 |
| D. 用该根 VWAP（`amount/volume`）或 `(open+close)/2` 成交 | ❌ VWAP 是全根结果，信号时刻还不知道；中点是一个谁都没见过的价格。它们比开盘价更"像真的"，因而更危险 |
| E. 涨跌停用经验阈值（"涨幅 ≥ 9.8% 视为封板"） | ❌ 魔数不认档差：ST 5%、创业板/科创板 20%、北交所 30%、新股首日不设限，全被一个数抹平；而 `gate.toml` 已经有这张表 |
| F. 委托未成交就逐根追单直到成交 | ❌ 做T 信号有时效，追单是"志在必得"的假设；且它把"今天没买到"变成"迟早买到"，直接抬高胜率 |

## 决定

1. **模块边界与依赖方向**：`backtest/{spec,limits,fills,position,engine,metrics,report}.py`，
   全部纯函数——只依赖 `domain/*` 与自己的数据结构，不 import `storage`、不 import `sources`。
   读盘、主数据、日历由 `zx-backtest` 这个 composition root 注入（与 `sources/jobs/daily.py` 同一个
   形状）。这不是洁癖：03-4.1 的"跑 3 次逐位相等"和 L1 的属性轰炸都要求引擎能在一个 `tmp_path`
   之外、不碰磁盘地跑起来。
   **Step 6c 补两点实现细节**（写在 ADR 里而不是只写在代码注释里，因为这条边界是要被机器判的）：
   composition root 的具体位置是 `backtest/cli.py`（入口点 `zx-backtest`），它是 `backtest/` 下
   唯一允许 import `storage`/`sources`/`tasks` 的文件；这条不靠评审自觉，由
   `tests/test_backtest_boundaries.py` 逐文件扫 import 判定——多一个越界文件就红，少一个也红。

2. **时钟 = `(trade_date, ts)` 全序，同刻按 `code` 二级排序**。排序键就是 `domain.bar.stamp_of`
   （ADR-0009 决定 3 的那把退化：日线 `ts=None` 自然排到当天之前）。同一时刻多只票的处理顺序必须
   写死，因为"字典序"是 03-4.1 点名的浮点不确定来源之一——不写死就有两份净值曲线，而它们都"对"。
   每根K线内的事件顺序固定为：**结算上一时刻挂着的委托 → 更新净值 → 问策略**。反过来（先问策略
   再成交）会让策略在同一根里既看见这根的收盘、又成交在这根的开盘，那是把时间倒流当常态。

3. **成交价 = 第 `delay_bars`（≥ 1）根之后的那根的 `open`，再按方向加滑点**（买加、卖减，
   对用户不利的一侧）。成交用的那根若不存在（停牌、尾巴断了、区间到头）→ 不成交，按第 4 条记原因。
   价格上界只受涨跌停板价约束（那是法规），**不夹进该根的 `[low, high]`**：夹进去等于把滑点偷偷
   抹掉，而滑点是 07 §5.2 明列要建模的现实。
   `delay_bars` 用**根**而不是分钟：引擎的时钟是K线根，换算成分钟要引入"这个 dataset 是几分钟"
   这个第二个事实。日报与回测报告把这个数翻译成分钟写出来（`delay_bars × 周期`），翻译在报告侧。

4. **不可成交有四条硬判定，全部拒单并记原因，一K线一判、不追单**：
   - **没有那根K线**：停牌、退市、当日全天无分钟行 → 没有可成交的时刻。这是结构性的，不依赖
     主数据的停牌区间（那份数据目前根本没有源，见代价三）。
   - **一字板**：`high == low` 且该价相对昨收的涨幅达上限（档位减一个固定余量，见决定 9 末段）→
     买方向封死买不到、卖方向
     卖不出（03-4.4 要的就是这个样本：能在跌停板上买入的回测引擎是骗子引擎）。
     **那句按方向读，不按"跌停"这个状态读**：一字跌停时卖出封死，而买入是整场最好成交的一笔
     （板上排满的是卖单）。把两种都拒掉等于替策略判死，也答错了 03-4.4 真正要防的那个谎。
   - **板价边界**：成交价不得越过该根方向的板价（买 ≤ 涨停价，卖 ≥ 跌停价）。
   - **流动性**：该根 `volume == 0`，或委托股数超过 `volume × max_participation_pct`。
   判序是口径不是随手写的：**制度先于流动性**（一根封死又没什么量的K线两样都缺，报告只记前者，
   封板的票谈不上流动性），**板判不出先于一切**（判不出板在哪就不该往下算有没有量）。
   上限档位与新股无限制窗口取自 `config/gate.toml` 的 `[defaults].limits_pct` 与
   `new_listing_no_limit_days`（唯一真源），但**不叠加 R004 的 `tolerance_pct`**：那 0.5% 是给
   "源把 10.00% 报成 10.03%"这种测量噪声留的，不是一条制度边界。R004 用 10.5% 判数据好坏，
   引擎用 10.0% 判能不能成交——同一个数、两种用途，所以判据本身要提到两边共用的地方：
   `quality/rules.py` 的 `_limit_and_board` / `_in_new_listing_window` 提入 `domain/limits.py`
   （档位与窗口天数），门禁与引擎各自只加自己那一层（容差 / 板价）。
   新股窗口那一天**不判一字**：真的没有板，就没有"封死"这回事。窗口内若有一只票封在某一价上，
   引擎会判成交，偏差方向 = 高估（代价二）。部分封板（开在板上但当天打开了）v1 也判**可成交**：
   分钟数据没有买量，再严就只能靠编。

5. **T+1 底仓台账**：可卖额度 = **当日期初底仓 − 当日已卖**，当日买入永不增加它。这一条同时给出
   验收 3 的三个答案——无底仓不能卖；当日买入不能当日卖；而"先买后卖"的 T入→T出 合法（卖掉的是
   底仓那 300 股，交易所层面只限制"当日买入的不可卖"，不区分卖出的是哪一批）。
   单位是 `lots × lot_size`（07 §二：每票每次 3 手 = 300 股）。
   **底仓不是一条 FIFO 腿**：它单独成一桶，入账价取该票在区间里第一根K线的开盘价——这是一个
   明写的**假设**（我们不知道用户何时买、买在多少），只用来定净值的起点，一个回合的盈亏都不碰它。
   于是 `round_trips` 里的每一笔两腿都是本次回测真实下过的单，胜率与 T飞率量的就是做T 的手艺，
   而不是底仓那几天的涨跌；底仓的 beta 全部走净值与 `Closing.base_pnl`，报告把两者分开印。
   **不引入现金约束**：现金可为负（T入 未还原就是占款，07 §二 把"不得已加仓"写成正常成本），
   保证金/两融属 07 §八 的"不做"。

6. **回合、T飞与加仓的会计口径定死**（07 §七 验收 5 要的就是这几个数能手工核算）：
   - **配对** = 同票同手数的 FIFO，**允许跨日**：第二天接回正是 T飞 的后续，按日切断就把亏损藏起来了。
   - **回合盈亏** = （卖价 − 买价）× 配对股数 − 两笔的全部成本。一次 T出 + 一次 T入、或一次 T入
     + 一次 T出，都是这一个式子，方向由谁先发生决定而不由策略预设决定（07 §二）。
   - **T飞** = 一次 T出 在**当日收盘时**仍无配对买入；**加仓** = 一次 T入 在当日收盘时仍无配对卖出。
     两者是事件计数，不额外产生盈亏（它的代价在之后的跨日配对里）。
   - 分母写死：`胜率 = 盈利回合 / 回合数`、`T飞率 = T飞 / T出成交数`、`加仓率 = 加仓 / T入成交数`。
     回合数为 0 时报告**明写"无回合"**，不许印一个 0.0%（04 §四 那条老规矩：没做和做完不能长一样）。
   - 期末未配对的净持仓按最后价格进净值，**不进胜率**，并在报告里单列"还有 N 手未平仓、浮盈亏 X、
     不在胜率分母里"。

7. **策略接口是纯函数**：`Strategy.signals(view) -> Signal | None`，`View` 只暴露**当前根及以前**
   的数据切片与自己的持仓台账快照；策略拿不到成交价（07 §一：只出信号，绝不下单）。
   Step 6 不写任何真策略——候选池是 Step 7 的事。本 Step 带一个 `NeverSignal` 与测试桩，
   03-4.2 的"对每个策略"在 Step 6 只能对桩成立，这是顺序而不是遗漏。

8. **成本参数的唯一真源是新增的 `config/backtest.toml` `[cost]`**，代码不留兜底默认（与
   `gate.toml` 同一条 fail-closed：缺配置就跑，好过用一个"看起来像"的费率跑出收益）。
   初始值取当期公开标准（佣金 0.025% 双边、单笔最低 5 元；印花税 0.05% 卖出单边；过户费
   0.001% 双边；滑点 0.02%）。用户的实际佣金率是配置值，改文件不改代码。
   同一份文件里的 **`[position]`（`lot_size` 一手股数、`base_lots` 期初底仓手数）同一条规矩**：
   缺这一节就报错，不兜底——"底仓几手"决定今天能 T 出去多少，填错的人为成本比没成本更危险。
   `lot_size` 是制度不是策略参数（主板与创业板的申报数量是 100 股或其整数倍），写成配置是因为
   "整手"这个模型换板块就不成立，见代价七。
   敏感性（03-4.3）= 同一 spec 乘 `{0.5, 1.0, 1.5}` 逐档跑，报告回答"正期望有没有反转"。
   乘的是 `[cost]` 全部五档，`[position]` 与 `[execution]` 一个都不乘：一手股数不是成本，
   把它乘进敏感性等于问一个没人问的问题（`with_cost_scaled` 的 docstring 同此）。

9. **引擎只吃后复权（`backward`）价，且涨跌停判定用相对量**（`query.read_bars` 一处换算，
   ADR-0009 决定 4）。这两条合起来解决了一个陷阱：涨跌停是**真实报价**上的制度，而真实报价在除权日
   会跳空——在 `raw` 口径里判板就得自己算除权参考价，而参考价没有源。在后复权口径里，同一天的
   open/close 乘的是同一个因子，**相对昨收的涨跌幅与口径无关**，判定照旧成立。
   于是既不用给引擎塞一套自己的因子换算（那正是 ADR-0002 第 3 条要防的复制），也不会把除权当成
   一笔假亏损。因子缺失时 `query` 抛 `Unadjustable`，加载即响，不留"悄悄退回 raw"的第三条路。
   **抵消不掉的只有板价的分数取整**：交易所把"昨收 × 幅度"四舍五入到分，真实涨停的涨幅因此可能比
   档位低一点点（10.03 元涨 10% 落在 11.03，只有 9.970%）。判据留一个常量余量
   （`limits.ALLOWANCE_PP = 0.5` 个百分点），而不是按价格现算：余量真正取决于**真实报价**里有几个
   半分钱，而真实报价不在引擎的口径里；后复权价 ≥ 真实报价，按后复权价算只会把余量算小。取常量
   还有一个好处：余量不随价格变，**判定与价格空间精确无关**（同批K线乘任意正常数，结果逐位相同），
   这条"与口径无关"必须是测出来的而不是推出来的：属性测试轰炸——同一批K线乘任意正常数，
   `fills.attempt` 整条流水线的判定结果不变（四条不可成交与成交那一支，连"是哪一条拦下的"一起比），
   成交价等比缩放，而 `fee` 明确不比——最低佣金 5 元是钱上的常数，与 `ALLOWANCE_PP` 同一性质。
   代价见代价六。

10. **产出与留痕**：`zx-backtest` 每次运行落 `${ZX_DATA_ROOT}/backtests/<运行时间戳>/`
    （`config.backtests_dir()` 新增），内含 `report.md` 与 `equity.csv`；同时 `zx-task backtest add`
    登记一行（策略+版本、参数哈希、区间、成本假设、样本内外指标、状态）。参数哈希 = spec 规范化
    JSON（键排序、`ensure_ascii=False`）的 sha256 前 12 位——台账要能认出"这就是同一次实验"。
    报告首段披露"这是该策略的第 N 次回测"（03-4.5），并带一句股票池的**幸存者偏差声明**：
    sina 分钟线不含退市票，池内若有退市票它的分钟行会整段缺失（R011 的 `no_minutes` 会报），
    偏差方向 = 高估可成交性与收益。
    **目录名用 UTC 秒级时间戳而不是 `<backtest_id>`**（Step 6c 的修订，原文写的是编号）：
    `report_path` 是登记时就必填的列，而编号与"第 N 次"要等插入之后才拿得到，报告首段又要引用它——
    顺序只能是 建目录 → 登记 → 写文件，所以名字必须先于编号定下来。撞名（同一秒跑两次）加 `-2`
    后缀而不是覆盖：覆盖上一次运行的报告等于抹掉一条留痕。代价是目录名不再等于台账编号，从产物
    反查台账要靠 `zx-task backtest list` 里的 `report_path` 那一列，不能靠肉眼对目录名。
    **票池与区间进参数哈希**也是有意的（原文未定）：换票池、换区间不是"同一份参数再跑一次"而是
    另一个实验，它该有自己的第 1 次。03-4.5 要防的是"改改参数挑最好那次报"——那件事由台账把每一行
    都留下来管，不由 `run_no` 把不同实验混进同一个计数。
    **状态由数字折出来，不是命令行给的**：`report.status(probes)` 看完三档成本判 `void`（三档全无
    回合，这一跑不成立）/ `fail`（符号反转，或最贵那一档期望不为正）/ `pass`（其余）。给一个
    `--status` 开关等于允许人敲一个"通过"进台账；09 §五 的留痕要的就是这个动作不存在。`pass` 只
    表示"成本敏感性这一条没翻脸"，**不等于满足 07-5.4 的全部启用门槛**（那一节的细目尚未补全）。

## 后果

- 正面：07 §5.2 列的四个现实（成本、延迟、不可成交、T飞/加仓）各自有一个可测的落点，
  07 §七 的五条验收全部能写成测试而不是评审意见。
- 代价一：成交在那根的**开盘**，所以"错过一根"与"买不到"在实现上是同一件事。这让它对
  `delay_bars` 敏感——而 03-4.3 的成本敏感性只覆盖成本，不覆盖它。报告必须把 `delay_bars` 与
  周期一起写出来，让人能看出结论有多依赖这个数。
- 代价二：一字板之外一律可成交，回测因此**高估**可成交性（决定 4 末段）。要收窄只能上 tick 或
  买五档，两者都不在 07 §八"不做高频"的边界之内是另一回事——它们根本没有免费数据源。
- 代价三：主数据的 ST 区间只从快照抓取日生效（`sources/akshare/master.read_master`），停牌区间
  根本没有源。所以回测区间里早于抓取日的日期**按非 ST 上限**判板，对 ST 票取宽了，偏差方向 =
  高估可成交性；报告必须写明这个日期分界。停牌那一半由决定 4 第一条接住（没有K线就是没有成交机会），
  不需要主数据。
- 代价四：`backtest` 进了 03 §一 的核心模块清单，覆盖率门槛 ≥ 90%。引擎是纯函数，这条门槛
  买的是"判据没人测"的风险，不是 IO 那半——IO 在 CLI 里，本来就不指望单测覆盖。
- 代价五：不写现金约束（决定 5）意味着回测不会告诉你"要多少钱"。它答的是"这套信号做T 划不划算"，
  资金占用留给 06 站点去报。
- 代价六：决定 9 那个固定余量在**昨收低于 1 元**的票上不够用（面值退市预警那一档，ST 的 5% 档最明
  显：0.24 → 0.25 是四舍五入上去的"涨停"，涨幅 4.17%，低于 `5.0 - 0.5` 的判据）。这类票会被判成
  "没封板"→ 照常成交，方向仍是高估可成交性，与代价二同向、不会反向。它被一个测试钉住而不是修掉：
  要修就得把真实报价灌进判定，那条路的尽头是自己算除权参考价（决定 9 刚省掉的那件事），而这类票
  本来就在 07 §二 的持仓池之外。
- 代价七："按整手说话"（`Signal.lots × lot_size`）只覆盖主板与创业板的报单制度——两地的申报数量
  是 100 股或其整数倍。科创板买入单笔不小于 200 股，北交所是"不低于 100 股、余额不足 100 股的部分
  一次性卖出"（《北交所交易规则》3.3.8），那里的单子根本不是"几手"。票池若纳进这两类（07 §二 的
  持仓池由用户维护，这件事归用户定夺），引擎会算出一笔**交易所根本不受理**的委托：偏差方向与代价二
  相同，仍是高估可成交性。v1 不为此加按板块分档的报单模型——票池里没有就不必先造。
