# ADR-0017 · 自定义组合的口径

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0011](0011-提示词组装的口径.md)、[ADR-0016](0016-估值组件进提示词的口径.md) ｜ **何时读我**：站点"自定义"组合的生成请求处理与校验；想放开自定义的字段或数据类型时（变更须新建 ADR）

- 状态：Accepted（2026-09-23，用户指令"有一个自定义按钮，自定义之后自己选输出的K线类型和多少天"）

## 背景

ADR-0011 决定 2 把模板钉在 YAML（改配置即生效）。用户要求站点提供"自定义"：自选K线类型与天数直接生成——这是**临场组合**，不该为它每次改 YAML（改了会影响所有后续生成），也不是模板（没有值得评审的固定组合）。

## 决定

1. **形态**：`/api/prompt` 接受 `template: "自定义"` + `custom.data`（`[{dataset, days}]` 列表）。壳按 ADR-0011 的同一套校验合成一条**一次性的 Template**——它不进 YAML、不留存、每次请求现造，生命周期就是这一次生成。
2. **可选范围（一期收窄）**：dataset 限K线四种（`daily`/`minute_5`/`minute_30`/`minute_60`），`days` 1–750；参考表（估值/预告）与字段自定义**不在**自定义范围内——那些是"口径"而非"深度"，口径必须走 ADR 评审（ADR-0016 的路），不能让一次临场点击带出新口径。
3. **固定文案**：role/task/output 是写死的一段通用分析文案（与 YAML 模板同级地进反幻觉头部约束），不由前端传入——前端传文案等于把提示词的"要求"部分交给不可信输入。
4. **校验**：dataset 未知、days 越界、data 为空、重复 dataset——全部 400 带原话，与模板装载同一 fail-closed 粒度。
5. **口径自证不变**：自定义组合的K线仍是后复权 + 表头自证（ADR-0011 决定 3），token 估算照走（决定 6）。

## 理由

用户要的是"看不同周期的组合"，不是"设计提示词"。把可变面收窄到 **dataset × days**，固定其余一切，是"灵活性"与"可信数据打包机"这块牌子之间的最小妥协面。

## 后果

- 前端的模板下拉多一个"自定义"项，选中展开周期选择器；后端多一条校验路径，测试覆盖四种非法输入。
- 未来若要放开字段或参考表组合，须先改本 ADR——这条路的门比 YAML 那条重。
