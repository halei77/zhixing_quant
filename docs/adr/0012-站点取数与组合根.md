# ADR-0012 · 站点取数与组合根：从模板到提示词的那一段怎么落地

> **层级**：L3 决策档案 ｜ **前置阅读**：[06-产品定义-提示词站点](../06-产品定义-提示词站点.md)、[ADR-0011](0011-提示词组装的口径.md)、[ADR-0003](0003-存储方案.md) ｜ **何时读我**：给站点加数据组件、改"要 N 个交易日"到日期区间的换算、或决定"提示词能不能碰盘"时（变更须新建 ADR）

- 状态：Accepted（2026-09-19）
- 决策人：agent，依据 06 §一/§四/§六/§八、ADR-0011 决定 1 与代价三
- 关联：01 路线图 Step 5、06 §四、06 §八-1/2/5、ADR-0011 决定 1/3/5、ADR-0010 决定 1（同一手法）

## 背景

ADR-0011 把 `site/` 定成纯层：模板装载、K线表格、token 估算、组装顺序，四样都不碰盘也不碰
HTTP。那个边界是有代价的，其中一条写在 ADR-0011 代价三：**dataset 的词表在盘上那一层**，纯层
只能把 `Selection.dataset` 当一个陌生字符串装起来。代价写完了，账还没还——现在要有人把
`{dataset: minute_5, days: 10}` 变成"从干净区读出这十天的那些根K线"，否则 06 §八-1（选定模板
即生成提示词）无从判起。

这一段没有一处是纯计算：交易日要日历、K线要读盘、复权要因子。所以它必须有一个"碰盘的地方"，
而项目对碰盘的地方的态度是一致的（ADR-0010 决定 1、Step 6 的 `backtest/cli.py`）：**收在一个
文件里，收在一处才查得清哪一行代码动过数据**。

三件事要定下来：

1. 这个组合根叫什么、被允许 import 什么、HTTP 与 LLM 调用进不进它。
2. `days`（交易日数）到日期区间的换算在哪做，日历从哪来。
3. 取到的比要的少时，提示词怎么说实话——那是 06 §一（防幻觉）在这条路上唯一的落点。

## 候选方案

### 取数放在哪

| 方案 | 评价 |
|---|---|
| **A. 放进 `site/table.py`**（表格组件自己去读盘） | ❌ 那等于把 ADR-0011 决定 1 撤销：表格是纯层被属性测试轰炸的对象，一旦它自己去读盘，"同一份输入必得同一张表"就变成"取决于盘上恰好有什么" |
| **B. 新建 `site/prompt.py` 作为唯一 IO 模块** | ✅ 采用。与 `backtest/cli.py` 同构，边界同样由 AST 扫 import 的测试守 |
| **C. 放进程入口 `tasks/`** | ❌ 站点是长跑服务，不是一个批处理任务；且那样 `site/` 的调用方向就反了（下层反过来依赖上层） |

### HTTP 与大模型调用进不进这个文件

| 方案 | 评价 |
|---|---|
| **A. 一起进**（`prompt.py` 里起服务、调模型） | ❌ 06 §一 明写"一期不做自动调用模型"，而且两件事的失败模式不同：取数失败是"报错"，调模型失败是"挂住" |
| **B. 都不进**，本层只交出字符串 | ✅ 采用。站点那层（渲染、复制、以及以后的推送）要多少种壳都行，字符串是唯一稳定的产物 |

## 决定

### 决定 1：`site/prompt.py` 是站点的 composition root，`site/` 下只有它能 import `storage`

与 `backtest/cli.py` 同一手法：`site/` 其余模块继续被"无盘环境下轰一万次"的测试覆盖，读盘这件事
集中在这一个文件。这一层的模块清单以本 ADR 为准（ADR-0011 决定 1 那份是 5a 时的历史状态，档案
只增不改）：

- 纯层：`site/{templates,table,tokens,compose}.py`
- 组合根：`site/prompt.py`

边界由 `tests/test_site_boundaries.py` 逐文件扫 AST 判，不是文档里的一句话——那个测试同时钉住
"纯模块清单 == 目录"与"IO import 只出现在 `prompt.py`"两个方向，改名或挪走都会红。

**数据根不写成参数**：与 `backtest/cli.py` 的 `_read` 同一条理由——查询层与采集层必须落在同一个
根上，能传根就等于可以传错，而"这根K线没数据"会变成假话。

### 决定 2：`days` → 日期区间的换算在根里做，日历由调用方注入

`Selection.days` 数的是**交易日**（ADR-0011 决定 3 的口径，与 `storage.query.Cover.days` 同）。
换算是"as_of（含）往回数第 days 个交易日"，用的是 `domain.calendar.TradingCalendar`。

日历**注入而不自己抓**：在生成一条提示词的路上起 HTTP 请求，失败模式就从"报错"变成"挂住"，
而站点是给人用的交互式工具（代价一）。谁持有日历谁负责它有多新——这条边界要老实写在代价里。

### 决定 3：取到的比要的少，改标题、不改数据

标题里的天数**必须是实际取到的天数**；与模板要的不符时，那句话写在标题里：

> 日K（盘上 42 个交易日，模板要 120）

宁可让大模型看见"数据少"，也不许它以为下面那张表有 120 天。这是 06 §一 在那条路上的唯一落点：
一份声称 120 天、实际 42 天的提示词，会让模型把"最近 42 天"读成"最近半年"，而它没有任何办法
发现自己被骗了——这与它凭训练记忆编一个价，是同一个错误的两个方向。

不补数据、不前向填充、不"取到多少算多少但不说"：三样都会让那张表看起来完整。

### 决定 4：dataset 词表由存储层判，这里不建第二份名单

`Selection.dataset` 原样交给 `storage.query.read_bars(dataset=...)`；不认识的 dataset 由
`storage.layout.dataset_spec` 响。这是 ADR-0011 代价三的兑现：**词表只有一份，在盘上那一层**。
这一层唯一自己写的字符串是表格小标题（`日K` / `5 分K`），它由 `layout` 的常量派生，
派生不出来就响（不猜中文名）。

### 决定 5：`status: pending` 的模板拒绝生成

pending = 它要的数据组件还没落地（06 §四 一期只有K线与基本信息；行业/流通股本这些在干净区里
没有出处，见坑 #30）。这一层见到 pending 就 `TemplateNotReady`，不是"少给一列照样出提示词"：
少一列的表看起来和满列的一样完整，而模型不会因为少了一列就说"数据未提供"——它会把那一列编出来。

同理，模板请求了 `turnover` 而调用方没给流通股本，`table.py` 的 `IncompleteComponent` 原样上抛，
不在这里兜 0。

### 决定 6：token 警告是给**人**看的，不进提示词

`Prompt` 带三个字段：`text`（交给大模型的）、`tokens`（估的数）、`warn`（超阈值那句话或 `None`）。
把"这段可能太长了"写进给模型的指令里，它会当成内容读——而且那句话的正确去处是站点界面
（06 §八-5 说的是"实时显示 + 超阈值警告"，是给人看的）。警告里点名 06 §六 唯一的省 token 手段：
换 `format: csv` 紧凑模式，或砍天数。

## 代价

- **代价一：日历新旧的责任在调用方**。本层不抓日历也不校验它覆盖到 `as_of` 之后的哪天；给一份
  过旧的日历，得到的是区间起点偏早的提示词，而标题里的"实际 N 天"会跟着错。缓解：站点那层
  每次盘后刷新日历（Step 8 的盯盘本来就要这个动作）。
- **代价二：`days` 是交易日数，不是"盘上真的有行的天数"**。一只票停牌 10 天，日历那 10 天照算
  在窗口里，读回来就只有 32 行——标题说的是 32。两个数都出现在这一页上（"要 120 / 盘上 42"
  里的 42 是**有行的交易日**），口径与 `query.Cover.days` 一致，方向是如实而不是好看。
- **代价三：一期只支持单票**。`table.render` 见到两只票就响（ADR-0011 决定 3），本层顺着它把
  `code` 定成单数；06 §九 的多股票对比留给后面，不留"先支持一半"的口子。
- **代价四：本层不碰 HTTP，所以它自己不能变成服务**。`zx-site` 那类入口还要一个薄壳；薄壳
  没有判定，只有参数与输出，故不为它单立 ADR。

## 一句话

**要 N 个交易日是模板的事，读出哪些天是盘的事，两件事相差几天必须写在标题里。**
