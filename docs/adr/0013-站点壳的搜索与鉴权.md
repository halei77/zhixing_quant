# ADR-0013 · 站点壳：搜索字典、口令与留痕

## 背景

ADR-0012 代价四写了句不那么准确的话：「`zx-site` 那类入口还要一个薄壳；薄壳没有判定，只有参数与
输出，故不为它单立 ADR。」开工第一天那句话就不成立了。06 §四 给一期壳列的三件事里，每一件都藏
着一个 06 没写完的判断：

1. **股票搜索**说的是"代码/名称/拼音模糊搜索"，没说什么算命中、两个都命中时谁排前面。而排序不
   定死，`match()` 就写不出能判的测试——"排在前面"是这个组件唯一的可观测行为。
2. **搜索留痕**说"上限 10 只；输入第 11 只时淘汰最早一只（FIFO）"，没说他说的话。而"上限 10
   只"这个量，是按条目数还是按不同的票来数，两种实现都自认符合那句。
3. **简单鉴权（固定口令）**（06 §二）没说口令放哪。放 `config/*.toml` 是最省事的写法，而仓库
   是公开的（05 §安全）；这个选择的错误表现是"部署成功"，不是"报错"。

还有一件事不是判断而是边界，但它要在这里落字：壳要读主数据与日历，而 ADR-0012 决定 1 说
`site/` 下只有 `prompt.py` 能 import `storage`。壳要不要成为第二个碰盘的位置、碰的是不是同一
样东西，边界测试正在等一个答案。

**本 ADR 只管壳的判定，不管它长什么样**：前端是 FastAPI 渲染还是静态页加 `fetch`，06 §二 已经
说过那是"实现层决策，可逆"，不需要一份档案。06 §四 的"基本信息"组件（行业、总市值/流通市值）
也不在本文里——那些字段在干净区里还没有出处，等它们入库时按 ADR-0012 决定 5 的路子走。

## 候选方案

### 搜索字典从哪来

ADR-0006 第 3 条批准了"阿里云侧部分辅助数据可直调 akshare（如搜索字典）"，并说可直调清单在
Step 5 细化。这份 ADR 就是那句细化，而答案是**这一项不必直调**：

| 方案 | 评价 |
|---|---|
| **A. 直调 akshare 的股票搜索接口**（`stock_search_spot` 一类） | ❌ 交互式页面上每一次按键都是一次外部 HTTP，而它的失败模式是"挂住"与"给了个跟干净区不同源的代码"。字典的唯一用途是把人敲的字变成 6 位代码，用不着问外部服务器 |
| **B. 用已有的主数据快照**（`sources/akshare/master.read_master`） | ✅ 采用。沪深两份名单已经是"在册全市场 + 简称 + 上市日"，已经带抓取日期（`manifest.csv` 的 `captured_at`），已经跑在既有的抓取流程里。新开一条实时搜索源等于给"这只票存不存在"准备第二份会漂的答案 |
| **C. 从干净区的K线分区反推代码表** | ❌ 那是"有行情的票"不是"能搜的票"：新上市的票搜不到是正常（它本来没有K线），但停牌一年的票也会一并消失，而它是有历史、值得生成提示词的 |

### 拼音那一路怎么实现

| 方案 | 评价 |
|---|---|
| **A. 一期不做拼音**（只代码 + 名称） | ❌ 那是把 06 §四 的功能表改小，属于放宽验收口径，不在 agent 的权限里 |
| **B. 自己抄一份声母表** | ❌ 一份 5000 字里查不到的生僻字表，错了没有任何信号（退市票简称里的生僻字正是 03 §L4 会撞上的那一类） |
| **C. `pypinyin` 现算首字母** | ✅ 采用。静态词表、不联网不读盘，纯层可用。代价是多音字按它的默认读音，见代价二 |

### 口令放在哪

| 方案 | 评价 |
|---|---|
| **A. `config/site.toml` 进仓库** | ❌ 站点是公网服务，仓库是公开的，两者之间只有一条"文件不该同时出现在两边"的常识 |
| **B. 环境变量 `ZX_SITE_TOKEN`，缺失即拒绝启动** | ✅ 采用。"没配口令"的表现必须是**起不来**，不能是"起来了，谁都能访问"——后者的日志与前者的日志长得一样，而它已经在裸奔 |

## 决定

### 决定 1：`site/` 的模块清单与碰盘位置（自本 ADR 起生效）

- 纯层：`site/{templates,table,tokens,compose,search}.py`
- 组合根：`site/prompt.py` —— **仍然只有它能 import `storage`**（ADR-0012 决定 1 那半句不变）
- 壳：`site/api.py` —— 可以 import `sources`（主数据快照、日历）与 `config`（路径），不可以
  import `storage`；要K线就调 `prompt.build`

ADR-0011 决定 1 与 ADR-0012 决定 1 各自那份清单是历史状态，档案只增不改；
`tests/test_site_boundaries.py` 指向本 ADR。边界测试从一条变成两条，方向不松反紧：

1. `storage` 这个 import **只**出现在 `prompt.py`（原样保留）。
2. `sources` / `config` / `tasks` 只出现在 `prompt.py` 与 `api.py`，其余模块一个都不许有。

把"读盘"拆成"读K线"与"读辅助快照"两个具名位置，仍然各自只有一个——这不是"谁都能碰盘"的开场，
而是让新增第三个碰盘位置时必须回来改这里。

### 决定 2：搜索是三路**或**，排序定死到能写测试

`site/search.py` 是纯层，两个动作：`Index(listings)`（把首字母表算一遍）与
`index.match(query, *, limit) -> tuple[Hit, ...]`，`Hit(code, name, listed_on, by)`。

首字母表在 **构造时**算，不在每次 match 时算。实测（2026-09-19 的沪深两份名单，4602 只在册）：
建索引 88ms，而一次 match 扫完四千多只是 1ms 量级——每次按键都重算就是白付八九十倍，而
06 §四 那格写的"模糊搜索"是个输入即搜的框。代价是字典与索引不同步，写在代价三。

- **空查询返回空**，不回全市场。06 §四 那格写的是"搜索"，一次回四千多条的响应不叫搜索；要列表
  是另一个组件（一期没有）。
- **代码路**：`by="code"`。查询里的数字（`sh600519`、`600519.SH` 这类写法都归到同一串数字）是
  代码的前缀即命中。这里不区分"完全相等"与"只是前缀"——代码是定长 6 位（`normalize_code` 保
  证），相等就只有一只有，两者不可能在同一份结果里争先后。
- **市场前后缀只在查询带着数字时才剥**。`sh600519` 里的 `sh` 是交易所，而单独敲的 `sh` 是两个
  拼音字母（`上海临港` 的首字母就是 SHLG）——一句话两种写法，剥与不剥各对一半，所以要写成一条
  规则而不是"看起来像前缀就去掉"。这条是拿真盘撞出来的：第一版不剥，`sh600519` 在 4602 只里返回
  20 条，19 条是 `沙河股份` 那一类，`SH` 成了拼音。两面各钉一条测试（`test_a_market_prefix…` 与
  `test_a_bare_prefix…`），只剥或不剥都会红一条。
- **名称路**：`by="name"`。查询是证券简称的子串即命中（中文子串，不做大小写以外的归一）。
- **拼音路**：`by="pinyin"`。查询大写字母化后，是"简称逐字首字母串"的子串即命中。
- **三路是或**：一路不中另两路照走。拼音是**加速器不是过滤器**——这句在代码里的形态是：多音字
  按 `pypinyin` 默认读音拼错时，名称那一路仍然会用汉字命中（代价二）。
- **排序**先按档位 `code < name < pinyin`，同档按命中位置，位置相同按代码升序。测试钉的是这条全
  序，不是"结果里有一只票"。
- **`limit` 必填**，默认由调用方（壳）给 20。纯层不藏一个"觉得够用"的数。

`Listing` 来自 `domain.security`（纯数据结构），所以这层不需要 as_of：主数据快照本身就只含在册
票，退市区间是 Step 3 的活，届时它带着日期一起来。

### 决定 3：数据端点全部鉴权，静态页不鉴权

口令从 `ZX_SITE_TOKEN` 读，未设置 → 启动即 `RuntimeError`，不是"跳过鉴权"。比较用
`secrets.compare_digest`（防时间侧信道是顺手的事，不是玄学：站点在公网上，而口令只有一个）。

一条规则划清哪些要鉴权：**回数据的一律要，回壳本身的不要**。`/api/*` 每个端点都要
`X-Token`；`/`（那个 HTML）与它的静态资源不鉴权——页面里没有任何数字，它含的最多是"这个站点存在"。
这条比"看路径前缀猜"好判定：新加端点时，它是否出现在鉴权范围内由它回不回数据决定，而写测试的人
不需要读实现就能判。

口令不进 URL 查询串（会落进访问日志与浏览器历史），只用请求头。

### 决定 4：留痕记的是**票**，不是敲过的字符串

06 §四 那句"最近搜索股票列表，上限 10 只；输入第 11 只时淘汰最早一只（FIFO）"里的量词是"只"，
所以：

- 同码再搜 → 移到队首，条目数不变。按"敲过的字符串"存的话，`茅台`、`600519`、`gzmt` 三次搜索就
  会把这只票自己挤掉两格，而上限说的是 10 只票。
- 淘汰的是队尾，也就是"最久没再搜的那只"。在去重后的序列上这与"最早一只"是同一个东西，两句不冲突。
- **服务端持久化**（06 §四 明写"刷新/重开不丢"）：数据根下 `site/recent.json`，一份 JSON 数组，
  每项 `{code, name, at}`。存 name 是为了重开时不必读主数据也能把列表画出来——那是显示用的副本，
  真值是 `code`（代价四）。

### 决定 5：壳不产生任何口径

`api.py` 里不许出现格式化、单位换算、天数推导：token 数、价格口径行、"盘上 N 天而模板要 M 天"
那句缺口，全部由 `prompt.build` 的返回值原样搬进响应。ADR-0012 代价四那句"薄壳只有参数与输出"
到这里才真的成立——它成立的前提是判定被前移进了这份 ADR 与纯层，不是壳的作者自觉。

## 补充决定（2026-09-20，Step 5d 前端落地时补）

决定 1 那份清单落地之后，壳里多了两样当时没写下来的东西：一张页，和一个关于字典覆盖面的实测事实。
都补在这里，不回去改上面那五条（档案只增不改）。

### 补充决定一：前端是包内三件静态件，零依赖、无构建步骤

`site/static/{index.html,app.js,style.css}`，由 `api.py` 以 `/` 与 `/assets/*` 发出。不引 Node
工具链：02 §一 的工具链只有 Python，而"构建一次产出一包 JS"会造出第二个真源（仓库里的 `app.js`
与盘上的产物），一次构建步骤也进不了 `uv run zx-site` 这条入口。页面要的东西只有 `fetch`。

`/` 与 `/assets/*` 不鉴权——这是决定 3 那句"回壳本身的不必"的第二次兑现：第一次是 404 走得到
路由，这次是真的把页发出去。口令由用户自己填进页面、存在 `sessionStorage`，静态件里不出现口令的
**值**（`test_the_page_and_its_assets_are_public` 钉住），路径按 `Path(__file__)` 反推（02 §六）。

### 补充决定二："实时 token 估算"的实时是"重新问服务器"

决定 5 说不许有第二套口径，而 06 §八-5 要"实时显示"——两者撞在这里。取舍：**估算函数只有一个，
在 `site/tokens.py`**；页面已出结果之后改模板或改截止日期会自动重发一次（400ms 防抖），未出结果
之前页面不猜任何数字。宁可显示 `—`，也不显示一个 JS 里另算出来的数：那个数字会和 06 §八-5 的
阈值判定不一致，而阈值判定就是这句警告存在的全部理由。

### 补充决定三：字典覆盖面实测＝沪深主板＋创业板，688 与北交所一只都没有

真盘上跑出来的事实，不是设计：主数据只有两份快照（`stock_info_sh_name_code/主板A股` 与
`stock_info_sz_name_code/A股列表`），4602 只里 `60` 开头 1702、`00` 开头 1494、`30` 开头 1406，
**`688`／`689` 与 `43`／`83`／`87`／`88`／`920` 各 0 只**。`_PREFIX_TABLE` 认得这些前缀
（`board_of("688981")` 不响），是名单里没有那些行——所以这不是搜索层能修的事。

后果写清楚：站点搜不到科创板与北交所，票池里也没有它们（同一个源，同一个流程），而 06 §四 那句
"退市股可搜"目前也无从谈起（快照里 `delisted_on` 全为空，在册即未退市）。修法是在 `sources/
akshare/master.py` 里加第三、第四份名单（科创板、北交所），属 Step 3 主数据范围的决定，**不由
站点单方面扩表**：扩了源就要跟着进门禁规则与票池范围一起裁决（04、08）。待用户裁决的那一格在
01 §Step 5 的"票池范围"里。

## 代价

- **代价一：多一个运行时依赖 `pypinyin`**（静态词表，安装体积 MB 级）。换它的替代方案是自己维护
  一份声母表，那是一份错了不会有任何信号的字典。
- **代价二：多音字按 `pypinyin` 的默认读音**，票名里的多音字可能拼在用户预期之外——`重庆啤酒` 的
  "重"给 `chóng`（cqpyj），按"zhòng"的读法搜首字母就落空。缓解是决定 2 那条"三路是或"：汉字子串
  那一路不看读音。真出现"常用读法与默认读音不符"时，加一张人工别名表，而不是改排序。
- **代价三：字典新旧 = 主数据快照新旧**，最长滞后到下一次 `tools/capture_golden.py`；而索引按决定
  2 是在启动时建的，所以重抓之后不重启就搜不到新上市的票。接受它，因为字典变化的频率是"一天一次"，
  而站点重启是免费的（部署侧本来就要发版）。真到了需要热重载那天，重建成按天重建，不是每次 match
  重建。新上市的票在快照刷新前搜不到，而它盘上本来也没有K线（同一条流程抓的），所以不会产生
  "搜得到却生成不出"的空窗；反过来，如果票有历史而字典没有（人工补录前的窗口），生成的提示词表为
  空，`table.render` 会响（`IncompleteComponent`），不是一张空表。
- **代价四：留痕是明文 JSON，不是数据库**，多进程同时写会互相覆盖。一期单人自用（06 §二"无多用户
  /权限体系需求"），接受。存了 name 副本就意味着它会与主数据不同步（改名后旧条目还是旧名）——判
  定时以 `code` 现查为准，`name` 只用于渲染那一行的空窗期。
- **代价五：口令只有一个、明文在环境变量里**，进程列表与 shell 历史看得到，且无轮换机制。这是
  06 §二 那句"简单鉴权"的直接代价，二期若把站点开给别人用，这条必须换掉。
- **代价六（2026-09-20 随补充决定一加）：口令在浏览器里多一份副本**。无账号、无会话，页与 API
  同源，用户填的口令存在 `sessionStorage` 里由 JS 逐个请求带上。于是"任何一处把外部内容当标记写
  进 DOM"都不再只是显示问题——那是一段能读走这串副本的脚本。缓解是结构性的：页面上所有外部文字
  （票名、提示词正文、报错原话）只走 `textContent`，`test_the_page_writes_text_and_never_markup`
  扫 JS 全文钉住这条；接受它，因为换掉的方案是会话与服务端状态，那不在 06 §二 的一期范围里。

## 一句话

**搜索的三路是"或"而拼音只是加速器；没配口令就起不来；留痕记的是票，不是敲过的字符串。**
