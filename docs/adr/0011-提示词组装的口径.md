# ADR-0011 · 提示词组装的口径：模板配置、K线格式与 token 估算

## 背景

Step 5 的站点只做四件事：选择、组装、预览、复制（06 §一）。其中"组装"是全站点唯一会
把数字交给大模型的地方，也就是 06 §一 那条定位（可信数据打包机）唯一的落点：一旦组装这一
步的口径含糊，站点就把"门禁后的干净数据"重新变回了"LLM 幻觉"——它要防的正是这件事。

三件事必须先定下来，否则 5a 写不出第一行：

1. **模板配置长什么样、放哪**（06 §五 要求"改配置即生效，禁止改代码"，但没说配置的字段边界）。
2. **K线进提示词的格式**（06 §六 定了 Markdown 表格、正序、价格 2 位小数、量额取整，但没定
   复权口径，而 `storage.query.read_bars` 的三种口径给出的价能差一个数量级）。
3. **"token 估算"是什么数**（06 §八-5 要实时显示 + 超 10 万警告，而项目没有 tokenizer）。

## 候选方案

### token 估算

| 方案 | 评价 |
|---|---|
| **A. 引 tokenizer（tiktoken 或等价）** | ❌ 站点面向"任意大模型"，词表与目标模型绑定；且多数词表要联网取，CI 里多一个网络依赖 |
| **B. 字符数启发式** | ✅ 零依赖、确定性、可测；代价是数字只是量级。06 §八-5 要的是"超阈值警告"，不是计费 |

### 模板格式

| 方案 | 评价 |
|---|---|
| **A. TOML**（与 `gate.toml`/`backtest.toml` 一致） | 仓库一致，但 06 §五 明写 YAML；多行"输出要求"在 TOML 里是三引号，比 YAML 块标量难读 |
| **B. YAML**（06 §五 原话） | ✅ 采用。依赖 `pyyaml` **显式声明**：现在它能 import 只是因为 akshare 顺手带了进来，隐性依赖正是 `pyproject.toml` 里 `pytz` 那条注释要避免的东西 |

## 决定

### 决定 1：`site/` 分两层，纯层不碰盘也不碰 HTTP

`site/{templates,table,tokens,compose}.py` 只准依赖 `site` 与 `domain`；读干净区、起 HTTP 的
接线留给 5b 的 `site/api.py`。与 ADR-0010 决定 1 同一个形状，也由
`tests/test_site_boundaries.py` 按 AST 守——06 §八-3 要的是"生成提示词中的数据与干净区抽样
比对 100% 一致"的**自动化对照测试进 CI**，而那种对照测试要能跑，前提就是组装这一段不需要
盘、不需要服务器。

### 决定 2：模板 = 角色 + 任务 + 数据选择 + 输出要求，全部在 `config/prompt_templates.yaml`

放仓库不放数据根，与 `gate.toml` 同一条理由（02 §六）：改口径必须出现在 git diff 里。
一条模板的四个部分：

```yaml
- name: 短期投资
  role: 你是资深 A 股分析师
  task: 判断未来 1–4 周的机会与风险，给出趋势、量价、支撑压力
  data:                       # 数据选择：dataset + 交易日根数
    - {dataset: daily,     days: 120}
    - {dataset: minute_60, days: 60}
  output: |
    先给结论，再给依据；每条依据引用具体K线的日期与价格。
  format: markdown            # 或 csv（06 §六 的"紧凑模式"）
  fields: [open, high, low, close, volume, amount]
  adjust: backward
```

`days` 数的是**交易日**，与 `storage.query.Cover.days` 同一口径（"有行的交易日"，不是日历天）。
换算成区间起点是 5b 的事——纯层只带"要几根"，所以它可以脱离盘上深度单测。

### 决定 3：进提示词的K线默认后复权，且表头必须自证口径

这是本 ADR 唯一一处 06 没写、必须新定的东西。两种口径各自的错法：

- 原始价：除权日会呈现为一根真实的大跌，大模型据此讲出一个不存在的技术破位——正是 06 §一
  要防的"数据异常"。
- 后复权价：趋势是真的，但**那个数不是现价**（600519 的因子在 8.88，后复权价比行情软件上的
  价高近一个数量级）。大模型引用它回答"现在多少钱"就是幻觉。

取后复权 + 强制一句口径说明（`table.py` 生成，不由模板作者手写，理由同决定 4）。三种口径各一句，
逐字就是 `table.ADJUST_LABELS` 里那三条——写在这里是因为**这句话是要被大模型引用出去的东西**，
改它等于改口径承诺，得与代码同一趟改：

| `adjust` | Markdown 表首行（CSV 模式同一句，前缀换成 `#`） |
|---|---|
| `raw` | `> 价格口径：不复权：价即行情软件上的价，但除权日会呈现为一根真实的下跌` |
| `backward` | `> 价格口径：后复权：趋势可读，这些数不是现价` |
| `forward` | `> 价格口径：前复权：基准是本段末日，末日那天的价即现价` |

那三句里不带 `**` 一类的 markdown 强调：同一段文字还要进 CSV 的注释行，星号在那里只是噪音
（`table.py` 顶部为此写了一句）。口径可配，但那句话跟着配置一起生成，三者都不会出现
"数没错、口径没说"的状态。选后复权而非前复权是因为前复权的基准是区间末日（`domain.adjust`
的口径），同一天的价会随窗口末尾变——提示词是要留档比对的东西，一个随窗口漂移的数没法复核。

### 决定 4：反幻觉固定头部由代码给，模板只能追加

06 §六 说固定头部"所有模板强制"。若它写在 YAML 里，那就等于"忘了写就没有"，而 06 §八-4
（所有模板输出均含反幻觉固定头部）就成了人肉检查项。所以 `compose.py` 把角色行与反幻觉指令
钉死在输出开头，YAML 的 `output` 只能接在后面。

### 决定 5：换手率缺分母就拒，不省列

06 §四 的可选字段含换手率，而换手率 = 成交量 ÷ 流通股本，流通股本不在干净区的K行里。
`table.py` 接受一个可选的流通股本，缺它又请求了 `turnover` 列 → `IncompleteComponent`。
静默少一列是最坏的一种"能跑"：提示词看起来完整，而大模型不会知道自己少了哪个维度。

### 决定 6：token 估算口径写死成字符启发式

CJK 字符 1 token、其余每 4 字符 1 token（向上取整）。阈值默认 100,000（06 §八-5），超了是
**警告不是拒绝**——生成什么由用户决定。这个数字的意义只有一个：给出"会不会爆上下文"的量级，
所以它必须是确定的、可复算的、跨模型不承诺准确的。

## 代价

- **代价一（token 数不准）**：换成任何非启发式的分词器，报出的数都会不同。缓解：阈值只作
  警告、且 06 §六 的"≈2 万 token"参考值本来就是量级说法。
- **代价二（后复权价不是现价）**：靠决定 3 那句口径说明兜。方向 = 大模型可能仍把后复权价当
  现价引用。这是"趋势可读"与"数字即现价"不可兼得时选的前者。
- **代价三（模板能声明盘上没有的 dataset/深度）**：纯层无从知道盘上有多少天，`days: 9999`
  在 5a 是合法的。5b 必须拿 `query.depth()` 对照并把缺口如实报出来（同 07 §5.1 的"可回测
  区间"处置）。
- **代价四（YAML 多一个运行时依赖）**：`pyyaml` 进 `pyproject.toml` 显式声明，代价是依赖面
  扩大一项；换来的是与 06 §五 一致、且"输出要求"这种多行文本在配置里可读。
