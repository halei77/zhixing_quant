# ADR-0008 · 隔离区落盘布局

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0002](0002-数据质量门禁架构.md)、[ADR-0003](0003-存储方案.md)、[ADR-0007](0007-数据存储位置.md) ｜ **何时读我**：写隔离区读写、或要回答"那天到底拒收了什么"时（变更须新建 ADR）

- 状态：Accepted（2026-09-19）
- 决策人：agent（布局细节），依据 ADR-0002 第 2 条与 04 §一「Step 3 与干净区一起做」
- 关联：01 路线图 Step 3、04 §一/§四、`storage/quarantine.py`

## 背景

ADR-0002 规定违规数据进隔离区、**不删不改**，供审计与报告；04 §四 又说日报只抽样 5 条，
"全量在隔离区可查"。可查的前提是它在盘上。Step 3a/3b 把干净区落了盘，隔离区仍只活在当次
运行的内存里——进程一退，那天拒收了什么就只剩日报上那 5 条。

难点不在体量（一天几千行），在**键**：一条被拒收的草稿，它的 `trade_date` 可能恰恰是缺失的
（R010 就是判这个），`symbol` 也可能归一不出来。干净区那套 `year=YYYY/symbol=XXXXXX.parquet`
分区语法建立在"行有一个确定的日期与代码"之上，而隔离区最该被审计的那几行正好没有。

## 候选方案

| 方案 | 评价 |
|---|---|
| **A. 按运行日一天一个 Parquet 文件** | ✅ 运行日永远已知，与行的质量无关；一天一文件正好对上"那天拒收了什么"这个提问方式 |
| B. 沿用 `year/symbol` 分区 | ❌ 缺日期/缺代码的行无处可放；给它们造一个 `year=unknown` 分区等于把语法变成两套规则 |
| C. 单个 DuckDB 库表 append | ❌ 重跑必产生重复条目，去重要靠 UPSERT 与跨批事务；而 Parquet 那条"读回来→合并→原子替换"的路子已在 Step 3a 付过学费（UNNEST 批量、`.part` rename、`hive_partitioning=false` 的列校验） |
| D. 违规清单存 JSON 字符串 | ❌ 按规则统计要靠字符串匹配，`list_contains(rules,'R004')` 与 `WHERE rules @> …` 的差别就在这 |

## 决定

1. **位置** `<数据根>/data/quarantine/`：与干净区同一个 `config.parquet_dir()`，不同 dataset 名。
   读写两侧都按 dataset 取目录，所以干净区查询接口天然看不见隔离区，反之也一样。
2. **文件粒度** 一天一个文件，文件名是**运行日** `YYYY-MM-DD.parquet`（不做 hive 子目录：
   一天一文件没有分区可裁剪，虚列只会多出一个要解释的东西）。装进去的是**那一次运行的整批**
   拒收条目，包括两日批里上一日那几行——文件名说的是"哪一次运行拒收了这些"，不是"哪一天被拒收"。
   这里的"运行日"取**那次运行的报告日**（`zx-daily --day`），不是墙上时钟那天：十天之后补抓
   2024-01-03，证据仍落在 `2024-01-03.parquet`，与当天的日报对得上。裁剪只发生在报给日报的那一侧。
3. **行形状** 一条 `QuarantinedRow` 一行 = `BarDraft` 全字段 + 三个**等长数组** `rules` /
   `levels` / `reasons`，位置一一对应，由同一个 `violations` 序列投影出来。除 `is_suspended`
   外全部可空，空就是"源没给"。
   **价格与量额存 `VARCHAR`，不是 `DOUBLE`**：DuckDB 1.5.5 把 Python 侧的 `nan` 绑进 `DOUBLE`
   会写成 `NULL`（实测；`inf` 反而原样保住），而"源给了 NaN"（命中 R001）与"源没给这个字段"
   （命中 R010）是两条不同的结论——审计文件里把一条洗成另一条等于伪造现场。代价是按数值筛要先
   `CAST`（`TRY_CAST('nan' AS DOUBLE)` 仍是 NaN，实测），而这里的读法本来就是"那天原始值是什么"。
4. **幂等键是整行**，不是 `(source, symbol, trade_date, rules)`：同一个键下原始值不同的两条，是
   源先后给出的两次各自成立的观测，不是一条事实的两种说法，所以两条都留。干净区正好相反——那里
   的两行是对同一天价格的竞争主张，存储层拒绝裁决，直接抛 `BarConflict`（ADR-0003）。于是这里的
   合并是**集合并**：后到的不覆盖先到的，重复由整行相等判掉。`zx-daily --limit 3` 的部分运行不许
   抹掉同一天全量运行留下的条目，这条与"重跑不产生重复"（01 Step 3 验收 3）都由
   读回→合并→内容没变就不写 来实现。
5. 落盘失败与干净区同一条取舍：不兜异常，让它冒到退出码。隔离区是审计证据，"今天没记下
   拒收条目"与"今天没有拒收"必须在盘上分得开。
6. **FATAL 整批不落这里**。判成 FATAL 的批次一行都不写：FATAL 说的是"这批读不出行"（快照缺失、
   列对不上），逐条落证据等于假装它们可读。这类事故由日报的告警与退出码记录，不占隔离区。

## 后果

- 正面：04 §四 那句"全量在隔离区可查"第一次成立；按日翻账与按规则统计都是一条 SQL。
- 代价一：同一条草稿命中多条规则时，三个数组要保持等长——合成一列嵌套结构与三列平行数组是有
  对齐风险的，选后者是因为按规则过滤是这里最常见的查询，而 DuckDB 的列表谓词作用在单列上最顺手。
  等长由构造保证（三条数组从同一个序列投影），不是由约定。
- 代价二：文件名是运行日，于是"这条拒收属于哪天"答的是"**哪一次运行抓到了它**"。同一个交易日的
  条目会散在几个文件里（今天的运行、明天补抓的运行各一次），而 04 §四 的提问方式恰好是"那天跑的
  时候拒收了什么"——两边对齐；代价是想按交易日看全量得 glob 整个目录。同一行被两次运行抓到时留下
  两条，那正是要留的：它们是两次独立的观测（决定 4）。
- 代价三：幂等键是整行，所以读回来的形状必须与写出去的形状完全一致。DuckDB 还给 Python 的是
  `list`，不把它变回 `tuple` 就是"每次重跑把整个文件再记一遍"，而日报看不出来。
- 隔离区不参与 ADR-0005 之外的备份安排：它就在数据根里，跟着数据根一起备。
