# ADR-0018 · 前端技术栈：Vue 3 + Vite（取代"零构建静态三件套"）

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0013](0013-站点壳的搜索与鉴权.md)、[11-设计规范](../11-设计规范.md)、[02-工程规范](../02-工程规范.md) ｜ **何时读我**：改前端技术栈、加前端构建/测试、部署站点前端时（变更须新建 ADR）

- 状态：**Accepted（2026-09-23，用户授权"你看着改吧"）**；决定 4 的"X-Token 头鉴权"半句已被 [ADR-0019](0019-站点撤销口令鉴权.md) 取代（2026-09-24）
- 决策人：用户 + 主线 agent
- 关联：ADR-0013 补充决定一（被本 ADR 取代）、ADR-0006（部署）、ADR-0012/0013（壳的契约不变）、11-设计规范

## 背景

ADR-0013 补充决定一当时选了"包内三件静态件、零依赖、**无构建**、不引 Node 工具链"，理由是：单页自用、02 §一 工具链只有 Python、避免为一个小页面引入构建链。

2026-09-23 情况变了：

1. 用户明确要求**不重复造轮子、用框架**，并要做一套系统化的 Liquid Glass 设计（见 11-设计规范）。
2. 手写单文件 CSS 在"系统化材质 / 组件状态 / 多页复用"上成本高：实测当前页已是**扁平风 + 同一种材质 + 无投影 + 一屏 5 层模糊 + 表单控件回落 Arial**，读起来不是毛玻璃。
3. 机器已具备 node 22 / npm 9，`tools/e2e` 已在用 Node Playwright——Node 工具链不再是"新增一种语言"，只是"新增一套前端构建"。

## 候选方案

| 方案 | 评价 |
|---|---|
| A. 保持零构建 vanilla | ❌ 满足不了"不造轮子 + 设计系统 + 多页复用"；系统化与组件状态手写维护成本高 |
| **B. Vue 3 + Vite + shadcn-vue（Radix Vue + Tailwind）** | ✅ 采用。组件成熟、主题变量能直接对接设计规范；Vue 与用户偏好一致 |
| C. React + shadcn/ui | ❌ 用户明确偏好 Vue；React 生态更重，无额外收益 |

## 决定

1. **前端源码进仓库 `frontend/`**：Vue 3 + TypeScript + Vite；组件基础用 **shadcn-vue**（底层 Radix Vue + Tailwind），主题 token 对接 `docs/11-设计规范.md`。
2. **构建产物由站点发**：`frontend/dist/` 由 FastAPI 以静态件发出（`/` 与 `/assets/*`）。**旧的 `site/static/{index.html,style.css,app.js}` 退役**，但保留到新前端通过功能验收（05 Q1-②）再删。
3. **开发与生产两条路**：
   - 开发：`vite dev`（默认 5173）proxy `/api/*` → `zx-site`（127.0.0.1:8000）。
   - 生产：`vite build` 产物随发布链路走，由 FastAPI/Caddy 发（ADR-0006 拓扑不变）。
4. **壳的契约不变**（ADR-0013 决定 5 等）：前端只调 `/api/*`、`X-Token` 头鉴权、**壳不产生任何口径**（格式化/换算/天数推导仍在服务端）、外部文字不拼 HTML、静态件 `Cache-Control: no-cache`。
5. **取代范围**：仅取代 **ADR-0013 补充决定一（前端形态）**。ADR-0013 的其余决定（搜索三路与排序、口令缺失即起不来、留痕记票、决定 1 的模块边界）继续有效；`site/api.py` 的静态件挂载点随之调整（改为发 `frontend/dist`）。
6. **CI 增加前端门禁**：`npm ci && vue-tsc --noEmit && vite build`（可选加 vitest / Playwright 组件测试）。02 §一 工具链表增列 Node/Vite/vue-tsc——属本 ADR 的**连带修订**，需与本 ADR 同批采纳。
7. **发布链路**：服务器无 node（ADR-0006 明示），故**本机构建、rsync `frontend/dist`** 到服务器（`tools/publish_site.sh` 加一步），不在服务器构建。
8. **设计契约**：视觉与交互一律以 `docs/11-设计规范.md` 为准；Tailwind 默认风格与目标相反，必须由 tokens 压住。

## 后果

- **正面**：组件复用、设计 token 系统化、多页（价值回归股票池页、做T 盯盘面板）可直接继承；不再手写重复组件。
- **代价一**：引入 Node 构建链与一份前端依赖，维护面扩大；CI 时间增加；发布多一步（本机构建）。
- **代价二**：`frontend/` 与 `site/static/` 会有并存期，期间"哪个是真前端"要写清楚（新前端通过验收前，`site/static` 仍是线上）。**迁移完成即删旧件**，不留第二份。
- **代价三**：Tailwind 的默认"模板感"正是要避免的；若 tokens 没压住，会做出"普通 Tailwind + 半透明"，验收按 11-设计规范 的截图自检。
- **连带**：02 §一 工具链表、ADR-0013 补充决定一的"零构建"表述需在新 ADR 生效时同步更新（文档与代码原子生效，02 §七）。
