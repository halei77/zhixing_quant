# ADR-0005 · 备份与灾难恢复

> **层级**：L3 决策档案 ｜ **前置阅读**：[ADR-0003](0003-存储方案.md) ｜ **何时读我**：质疑备份方案时（变更须新建 ADR）

- 状态：Accepted（2026-09-17）

## 背景

上一版项目以"删除仓库 + 重置服务器"告终，代码与数据全毁。本次数据集中于 E 盘（ADR-0003），单盘即单点。必须假设：磁盘会坏、误删会发生、系统会重装。

## 决定

1. **备份对象**：E 盘数据（Parquet/DuckDB/回测产物）+ git 仓库（含文档）+ 任务流水线库
2. **介质**：**网盘**（用户选定，零成本；接受其速度与稳定性一般的代价）
3. **频率**：每日 02:00 增量 + 每周日 03:00 全量；保留最近 3 代全量
4. **实施时机**：**延后至阶段二完成、有真实数据之后启用**（用户决议：现在没有内容可备份）；首个备份任务随 Step 5 验收落地
5. **恢复演练**：启用时完成首次演练，此后每季度至少一次——随机挑一个数据集从备份恢复到临时目录并校验可读。**没演练过的备份等于没有备份**
6. git 仓库推送到远端（GitHub/Gitee 私有库），代码与文档天然双份

## 后果

- 正面：任何单点故障最多损失一天数据增量；零成本
- 代价：网盘同步速度与稳定性一般，大数据量全量同步耗时需观察；恢复依赖网盘可用性
